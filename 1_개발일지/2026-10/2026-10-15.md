## block2
### 1. 구현 목적: Source code profiling 
[구현코드](https://github.com/hardthink26/review_app_project/blob/c0a0bb80372c68f8788bfc548896dfbd73ed9cb6/flasky.py#L52-L61)

### 2.개발흐름 :
1. command line 입력 제작 + 필요 parameter설정 
	- length: 출력할 함수 개수를 제한합니다. 
	- profile-dir: profiler data를 디렉터리에 저장합니다. 
2. profile function 제작 
	- werkzeug 모듈을 이용합니다.(ProfilerMiddleware)
		- 각 request를 프로파일링하는 middleware 객체를 제공합니다. 
			- 각 argument는 profile_dir& restrictions를 사용

### 3.병목점/이유: 
- 왜 restrictions = [lengh]처럼 list 형식으로 작성을 해야했는가? 
	- werkzeug docs기준 restrictions 는 출력제한 조건들을 iterable형태로 받는다. -> length는 정수이므로 restrictions=[length]로 전달하며, 출력할 함수 항목 수를 제한한다. 
- Flask CLI에서 서버가 시작되지않는 문제 
	- flask profile 명령 내부에서 app.run()을 호출하면 flask가 실행 차단 
	- **해결책** 
		- werkzeug.serving.run_simple()로 서버를 시작하도록 수정
