### 2.개발흐름 :
- API -> blueprint로 관리 
- Error 관리 
	- ex)404, 500에러 같은 경우 서버는 HTML을 반환-> API는 JSON형식을 원하기에 혼동 -> **HTML보다는 JSON형식으로 오도록 설정 ** 
- Authentication with HTTPauth 
	- 왜 사용하는가? 
		- 보통은 세션 기반 형태의 인증을 통해 로그인 상태를 저장 -> 요청마다 인증 정보를 전달하고 서버가 독립적으로 인증 가능하도록 함  
		- solution: **HTTPAuth**형식 사용 
	- 개발 세부 흐름 
		- User Model에 토큰 생성 & 검증 기능 구현 
		- 토큰 검증 함수 제작 
			- 검증 수단: Password, email, token 
			- 만약 패스워드 파트가 비었다면 email_or_token파트를 검증하는 로직 작성 
			- 토큰으로 인증 시 g.token_userd=True -> 기존 토큰으로 새 토큰 반환 방지 
		- 토큰 발급 함수 제작 
			- 조건: g.current_user가 is_anonymous가 True거나 이미 토큰 보유했다면 -> 접근거부 
			- 아니라면 토큰을 발급 + jsonify메소드를 사용해 response형태로 반환 
- Serializing Resources to and from JSON 
	- 점검 포인트: 
		- 클라이언트들에게 어떤 정보를 줄 것이고 어느 정도 까지 필요한가? 
- Pagination of Large Resource Collections 
	- 왜 필요한가? 
		- 만약 포스트를 전부 다 반환해 클라이언트에게 요청 시, 매우 큰 비용 발생 
		- 정해진 분량만 지급 + 나머지는 URL형태로 앞뒤 페이지로 지급 

	- **How?**
		- 현재 페이지 포스트 제공 + 앞 뒤 페이지 url 등의 메타 데이터 제공
