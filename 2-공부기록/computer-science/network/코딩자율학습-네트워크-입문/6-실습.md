## 클라우드 컴퓨팅과 GCP
- 과거에는 웹 사이트 운영하려면 물리적 서버 컴퓨터를 구매하고, 이를 직접 설치할 서버실 마련하고 유지했어야함
- **온프레미스(on-premise)** 
	- def.
		- 기업이나 개인이 자체적으로 IT인프라를 소유하고 운영하는 방식 
	- 특징 
		- 초기 서버 구축 비용 많이 듬, 유지보수 힘듦
		- 네트워크 통해 주고받는 데이터의 양, 즉 트레픽이 갑자기 증가시 유연 대처x 
- **cloud computing(클라우드 컴퓨팅)** 
	- 정의
		- 온프레미스 단점 해결 위해 등장, 인터넷을 통해 서버, 스토리지, 데이터베이스, 소프트웨어 등과 같은 자원을 필요한 만큼 빌려서 쓰고 사용한 만큼만 비용 지불 
	- 장점 
		- 비용 효율성
			- 직접 구매할 필요 없어서 초기 투자 비용이나 운영 비용이 절감 
		- 운영 유연성 
			- 각 요구에 따라 컴퓨팅 자원의 양을 조절 가능 
		- 구축 신속성 
		- 관리 용이성 
			- 하드웨어 유지보수, 소프트웨어 업데이트, 보안 패치 등 인프라 관리에 대한 부담을 클라우드 제공 업체(CSP, Cloud Service Provider)가 상당 부분 부담 
		- 글로벌 서비스 
	- 대표 서비스 업체 
		- 구글의 GCP(Google Cloud  Platform) 
		- 아마존의 AWS(Amazon Web service) 
		- ms의 Microsoft Azure 

### SFTP로 파일 전송하기 
- SFTP란? 
	- SSH연결을 바탕으로 파일을 암호화해 전송하는 파일 전송 프로토콜 

### https의 작동 원리 
- 순서 
	1. 도메인 이름 확보 
	2. SSL/TLS 인증서 발급 
	3. 서버 설정 및 변경 및 인증서 적용 
- **SSL/TLS**인증서 
	- 웹브라우저와 웹 사이트 간에 데이터를 주고받을 때 누군가가 내용을 엿보거나 위변조하는 것을 막기 위해 등장 
	- 웹 브라우저와 웹 사이트 간에 암호화된 연결을 하기 전에 웹 사이트가 진짜임을 증명하는 디지털 신분증 느낌 
	- 포함되는 정보 
		- 웹 사이트의 도메인 이름
		- 웹 사이트의 공개키
		- 인증서를 발급한 인증 기관의 정보 
		- 인증 기관이 남긴 디지털 서명 
	- 수행하는 보안 기능 
		- 인증서 인증 
		- 디지털 서명 인증 
			- SSL/TLS인증서는 인증 기관이 남긴 디지털 서명을 포함 
			- 웹 브라우저는 인증서에 있는 디지털 서명을 검증함으로써 인증서가 전송 과정에서 변조되지 않았음을 확인 
		- 암호화된 데이터 전송 
			- 검증 마친 웹 브라우저와 웹 사이트는 서로만 알 수 있는 세션 키(session key)를 만들어 공유 
			- 이후 주고받는 모든 데이터는 세션키로 암호화해 전송함으로써 통신 데이터 보호합니다.

### 인증 기관 
- SSL/TLS인증서는 인증 기관(Certificate Authority)이 발급
- 대표 기관 
	- let's Encrypt 
### 신뢰 체인 
- 실제 웹 사이트에 발급되는 SSL/TLS인증서는 계층 구조 발급 
	1.  최상위 인증 기관이 중간 인증 기관의 인증서를 발급
	2. 중간 인증 기관이 최종적으로 웹 사이트의 인증서를 발급
- 이러한 연결 고리를 신뢰 체인(chain of trust)혹은 인증 경로(certification path)라고 합니다. 
- 인증 기관의 디지털 서명은 신뢰 체인에 따라 진행 
	1. 최상위 인증 기관은 중간 인증 기관의 인증서 내용을 해싱한 뒤 자신의 개인키로 암호화해 디지털 서명
	2. 중간 인증 기관은 웹 사이트인증서 내용을 해시한 뒤 자신의 개인키로 암호화해 서명 
	3. 이렇게 발급된 웹 사이트 인증서와 중간 인증 기관 인증서는 각각 상위 기관의 인증서를 포함
