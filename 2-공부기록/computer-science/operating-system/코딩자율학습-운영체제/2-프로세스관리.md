## 프로세스 개요
- 프로세스는 실행 중인 프로그램으로, CPU,memory 등 시스템 자원을 할당받아 동작합니다. 

### 프로세스란
- 프로그램
	- 어떤 작업을 수행하는 코드 집합 
	- 여러 명령어로 구성
	- 보조 기억 장치(이하 디스크)에 파일 형태로 저장됩니다. '
- 프로세스
	- 사용자가 컴터에서 프로그램을 실행하면 운영체제는 주 기억 장치에서 적절한 공간을 찾아 프로그램을 load합니다. 이 과정에서 디스크에 있던 프로그램의 실행 파일 코드와 데이터를 메모리로 가져옵니다. 
	- 이렇게 메모리에 로드되어 실행 중인 프로그램을 process라고 합니다. 
		- 운영체제는 메모리를 효율적으로 관리하기 위해 프로그램의 전체 코드와 데이터를 한꺼번에 로드하지 않고 필요할 때마다 일부만 가져옵니다. 

### 멀티프로세스(Multi-process)
- 한 프로그램이 여러 프로세스로 실행되는 구조를 의미합니다. 
- 멀티프로세스 환경에서 같은 프로그램이 여러 번 실행되더라도 각각은 독립적인 프로세스로 동작 

### 포어그라운드와 백그라운드
- **background process**
	- 사용자와 직접 상호작용하지 않고 화면에 보이지 않는 상태에서 실행되는 프로세스
	- 일반적으로 컴터가 부팅될 때 자동으로 시작되어 컴터 종료할 때까지 계속 실행 
- **foreground process**
	- 사용자가 직접 실행하고 사용자 인터페이스를 통해 상호작용하는 프로세스

### 프로세스의 메모리 구조 
- 운영체제는 컴퓨터의 가장 중요한 시스템 소프트웨어입니다. 
- 운영체제는 커널영역과 사용자 영역으로 메모리를 분리해 관리 
	- 영역을 분리함으로써 프로그램이 운영체제의 중요한 메모리 영역에 접근해 수정하는 것을 방지 가능 
- 커널 영역에는 운영체제의 요소인 커널이 위치하고, 모든 프로세스가 공유
- 프로세스가 생성되면 사용자 영역에 각자 독립적인 메모리 공간을 할당받습니다. 
	- 이 공간은 코드, 데이터, 힙, 스택 영역으로 나뉩니다. 

- **코드 영역**
	- 정의
		- 프로그램 실행에 필요한 명령어를 저장하는 영역 
		- CPU가 직접 읽어 실행하는 부분으로, CPU가 이해하고 실행 가능한 기계어로 작성됨 
	- 코드 영역은 일반적으로 읽기 전용으로 설정
		- 프로그램 실행 동안 코드가 변경되지 않도록 보호
	- CPU는 코드 영역에서 명령어를 하나씩 읽어와 순차적으로 실행합니다. 
	- 유닉스 또느 리눅스 시스템에서는 코드를 텍스트 형식으로 작성해서 코드 영역을 **텍스트**영역이라고도 합니다. 
- **데이터 영역**
	- 프로그램을 실행하는 동안 유지해야 하는 데이터(전역 변수, 정적 변수, 상수 데이터)를 저장하는 영역입니다. 
	- 프로그램을 메모리에 로드할 때 데이터 영역에 필요한 데이터가 할당됩니다. 
- **힙 영역**
	- 프로그램을 실행하는 동안 동적으로 메모리를 할당할 수 있는 영역입니다. 주로 객체나 동적 배열을 저장 
	- 힙 영역의 크기는 프로그램이 실행되는 동안 운영체제가 조정합니다. 
- **스택 영역**
	- 프로그램을 실행하는 동안 사용하는 데이터를 저장하는 영역입니다. 
	- 주로 함수 호출 시 생성되는 지역 변수, 매개변수, 반환값 등을 저장합니다. 
		- 함수를 호출시마다 스택 프레임이라는 메모리 블록이 새로 생성됩니다. 이 프레임에는 함수의 지역변수와 매개변수, 반환값 등이 저장되고, 함수 실행이 끝나면 스택 프레임은 제거됩니다. 
	- 스택은 LIFO구조로 동작합니다. 
	- 스택 영역의 크기는 프로그램 실행 중에 일정 범위 내에서 동적으로 변동될 수 있지만, 일반적으로 스택의 최대 크기는 실행 환경에 따라 제한이 있습니다. 
		- 스택 영역을 많이 사용하면 스택 오버플로가 발생할 수 있습니다. 

### PCB(process control block)
- 각 프로세스에 대한 정보를 관리하기 위해 사용되는 데이터 구조입니다. 
- 프로세스가 생성될 때 운영체제가 PCB를 생성하고, 프로세스가 종료되면 제거합니다. 
- PCB는 커널에 위치하며, 사용자 프로세스가 직접 접근 불가 
- **PCB에 저장되는 정보들**
	- 프로세스 식별자(PID, process ID)
		- 운영체제가 각 프로세스를 구별하기 위해 부여하는 고유한 식별 번호 
		- 용도 
			- 프로세스 간 통신 
			- 시스템 자원 관리 
			- 부모-자식 관계 
	- 프로세스 상태(process state)
		- 각 프로세스가 현재 어떤 상태에 있는지 나타냅니다. 
	- 프로그램 카운터(PC, program counter)
		- CPU레지스터 중 하나로, 현재 실행 중인 명령어 다음에 실행할 명령어의 주소를 저장 
		- CPU가 명령어를 실행할 때마다 PC가 자동으로 증가해 다음 명령어의 주소를 가리킴 
	- 레지스터 상태 
		- CPU내부에 있는 아주 빠른 저장 공간으로, 명령어를 처리하고 연산을 수행하는데 필요한 데이터를 임시로 저장
		- register state는 현재 저장된 값들을 의미하며, PCB에 이를 저장
		- 컴퓨터는 여러 프로세스를 동시 실행할 수 있는 멀티태스킹 기능이 있습니다. 
			- 한 프로세스가 실행 중일 때 다른 프로세스가 CPU를 사용해야 할 경우, 현재 진행 중인 프로세스를 멈추고 다른 프로세스로 전환해 실행합니다. 이 과정에서 현재 프로세스의 레지스터 상태를 PCB에 저장합니다. 
	- 메모리 관리 정보(memory management information)
		- 프로세스를 실행하는 동안 필요한 메모리 자원에 대한 정보를 의미합니다. 
	- 작업계획정보(scheduling information)
		- 프로세스의 실행 순서와 CPU할당을 관리하기 위해 저장하는 정보 
			- 이 정보는 멀티프로세스 환경에서 CPU가 여러 작업을 공정하고 효율적으로 처리하는 데 중요 
		- **포함 정보**
			- 프로세스 우선순위 
				- 각 프로세스는 중요도에 따라 우선순위(priority)가 있습니다. 
				- 우선순위는 운영체제나 사용자가 설정할 수 있습니다. 
			- 스케쥴링 큐 포인터
				- 운영체제는 여러 프로세스를 관리하기 위해 스케쥴링 큐를 사용 
					- scheduling queue는 준비 상태에 있는 프로세스의 목록으로, CPU할당을 기다리는 프로세스가 대기하는 공간입니다. 
				- 작업 계획 정보는 각 프로세스가 현재 어느 큐에 있는지 나타내는 포인터를 포함합니다. 
			- 대기 시간과 경과 시간 
				- 대기시간은 프로세스가 준비상태에서 CPU를 할당받기 위해 대기하는 시간을 의미 
				- 경과시간(elapsed time)은 프로세스를 실행한 총 시간을 의미합니다. 
			- 프로세스 계정 정보(accounting information)
				- 각 프로세스가 시스템 자원을 어떻게 사용하고 있는지를 추적하고 관리하는 데 필요한 정보를 저장합니다. 
				- **포함 정보**
					- CPU사용시간
					- 메모리 사용량
						- 프로세스가 수행한 입출력 작업의 횟수와 양에 대한 정보를 기록
					- 실행 시작 시간과 종료 시간
					- 사용자 ID와 그룹 ID
						- 프로세스를 실행한 사용자의 사용자ID와 그룹ID를 저장합니다. 
					- 페이지 폴트 수 
						- page fault는 프로세스에 필요한 데이터가 메모리에 없을 때 발생 
			- 입출력 상태 정보(I/O status information)
				- 프로세스가 입출력 작업을 수행하는 동안 해당 작업에 대한 정보를 저장 
				- **저장 정보**
					- 열린 파일 목록 
						- 프로세스가 읽거나 쓰기 위해 열어 둔 파일들의 정보 
					- 입출력 요청 큐
						- 프로세스가 요청한 입출력 작업들이 대기하고 있는 큐 
							- 이 큐에 대기 중인 작업들은 운영체제의 입출력 스케줄링 알고리즘에 따라 순서대로 처리됩니다. 
## 프로세스의 상태 
- 운영체제가 프로그램을 실행하는 동안 프로세스가 어떤 작업을 수행 중인지, 어떤 자원을 기다리는 지 나타냅니다. 

### 프로세스의 생성 
- 사용자가 컴퓨터에서 프로그램을 실행하면 새로운 프로세스를 생성
- 컴퓨터를 켤 때도 여러 프로세스가 자동으로 생성됩니다. 

### 부모-자식 프로세스의 관계
- 기존에 실행 중인 프로세스가 새로운 작업을 처리하기 위해 다른 프로세스를 생성할 수도 있습니다.
	- 이때 기존 프로세스를 **부모 프로세스**, 새로 생성한 프로세스를 **자식 프로세스**라고 합니다. 
	- 자식 프로세스는 보통 부모 프로세스의 일부 자원(환경 변수, 파일 핸들, 메모리 공간의 복사본등)을 상속
### 프로세스 ID와 부모 프로세스 ID
- 운영체제는 각 프로세스를 관리하기 위해 고유한 **Process ID(PID)** 를 할당
	- 새로운 프로세스가 생성될 때 기존 프로세스의 ID를 부모 프로세스ID(PPID, Parent Process ID)로 저장
### 초기 프로세스
- 운영체제가 실행될 때 가장 먼저 생성되는 프로세스를 **초기 프로세스** 또는 **루트 프로세스**라고 합니다. 
	- 초기 프로세스는 운영체제의 핵심 프로세스로 생성되어 다른 모든 프로세스를 생성 & 관리 
- 초기 프로세스의 역할 
	- 시스템이 정상적으로 동작할 수 있도록 시스템의 주요 서비스와 데몬을 실행
	- 프로세스 관리와 자원 할당 등을 수행합니다. 
		- 예시)
			- 윈도우의 초기 프로세스는 System
				- 부팅 과정서 가장 먼저 생성되며, PID는 일반적으로 4를 할당 
			- 맥OS는 launchd
				- PID는 1 
				- 시스템 초기화, 시스템 서비스 및 데몬 관리, 사용자 로그인 및 세션관리를 담당 
			- 유닉스와 리눅스에서는 init프로세스 
				- PID는 1
				- 현대 리눅스 배포판에서는 systemd를 사용합니다. 
- 데몬 VS 서비스 
	- 데몬 
		- 리눅스와 유닉스 계열 운영체제에서 주로 사용하는 용어
		- 백그라운드에서 실행되는 시스템 서비스를 의미 
		- 데몬의 이름은 보통 'd'로 끝나는 경우가 많다. 
	- 서비스 
		- 주로 윈도우 운영체제서 사용하는 용어 
### 프로세스 상태 전환 
- 프로세스가 시스템 자원을 어떻게 사용하는지에 따라 프로세스를 여러 상태로 구분하고 관리 
	- **생성(new)**
		- 프로세스를 생성한 상태 
		- 운영체제는 프로세스를 생성하고, 필요한 자원을 초기화
	- **준비(ready)**
		- 프로세스의 실행준비가 완료되어 CPU가 할당되길 기다리는 상태
		- 이 단계에서는 CPU의 다른 자원은 할당되지 않습니다. 
	- **실행(running)**
		- 프로세스에 CPU가 할당되어 작업을 수행하는 상태입니다. 
		- CPU가 할당되는 순간 프로세스는 명령어를 순차적으로 실행 
	- **대기(waiting/blocked)**
		- 파일 입출력이나 네트워크 통신과 같은 이벤트가 발생해 해당 작업이 완료되기를 기다리는 상태입니다. 
		- 이 단계에서는 시스템 자원을 사용하지 않고 해당 작업이 완료될 때까지 대기 
	- **종료(termination)**
		- 이 단계에서는 운영체제는 프로세스에 할당한 모든 자원을 해제 
- 상태 전환 과정 
	- 생성 -> 준비 
		- 운영체제는 프로그램 코드와 데이터를 메모리에 로드하고 PCB를 생성
	- 준비 -> 실행
		- 준비 상태의 프로세스 중 하나가 선택되어 CPU를 할당받으면 실행 상태로 전환 
		- **디스패치**
			- 운영체제의 CPU 스케줄러가 프로세스를 선택하는 과정을 의미 
	- 실행 -> 준비 
		- 프로세스가 실행 중 할당된 CPU 시간을 모두 사용하면 다시 준비 상태로 전환 
		- 전환 조건 
			- 설정 시간 초과 
			- 운영체제가 우선순위가 높은 다른 프로세스를 실행토록 결정 
	- 실헹 -> 대기 
		- 프로세스가 입출력 요청, 네트워크 작업 또는 특정 이벤트 발생을 기다려야 할 경우, CPU를 반납하고 대기 상태로 전환 
	- 대기 -> 준비 
		- 대기 상태의 프로세스가 기다리던 이벤트가 완료되면 다시 준비 상태로 전환 
	- 실행 -> 종료 
		- 프로세스가 실행을 종료하거나 오류가 발생해 종료 
- 운영체제가 프로세스를 관리하는 이유
	- CPU, memory, I/O device 등 시스템 자원을 효율적으로 관리해 자원의 낭비를 줄이고, 시스템의 성능 향상 도모를 위함 
	- 프로세스를 동시에 실행해서 사용자가 여러 작업 동시 수행토록 합니다. 
### 인터럽트 유형 
- 인터럽트란? 
	- CPU가 현재 실행 중인 작업을 일시 중단하고 중요 이벤트를 처리하도록 하는 신호로, 하드웨어 또는 소프트웨어 요청으로 발생 
	- **유형**
		- 타이머 인터럽트 
			- CPU 스케줄링에 따라 일정 시간이 지나면 발생 
		- I/O interrupt
			- 키보드 입력, 디스크 입출력, 네트워크 패킷 수신 등으로 발생 
		- 소프트웨어 인터럽트 
			- 프로그램이 시스템 호출을 하면 발생 
		- 예외(exception)
			- 0으로 나누기, 메모리 접근 오류 등이 발생하면 CPU가 처리 요청 
### 컨텍스트 스위칭 
- 멀티프로세스 환경에서는 여러 프로세스가 동시에 실행되는 것처럼 보이지만, 실제로 CPU는 한 번에 하나의 프로세스만 실행합니다. 이를 **동시성(concurrency)** 라고 합니다. 
- 이렇듯 프로세스를 빠르게 전환하며 실행하는 과정에서 컨텍스트 스위칭이 발생
	- 컨텍스트 스위칭(context switching)은 운영체제가 하나의 프로세스를 실행하다가 다른 프로세스로 전환하는 과정을 의미 
		- context는 현재 실행 중인 프로세스의 상태를 포함한 모든 정보를 의미 
- 문제점 
	- CPU가 여러 프로세스를 관리하는 데 필요하지만, 이때 발생하는 오버헤드로 CPU 자원을 소모 
	- 컨텍스트 스위칭이 자주 발생하면 CPU는 실제로 작업을 수행하는 것보다 상태를 저장하고 복원하는데 더 많은 시간을 소모 
		- **오버헤드(overhead)**
			- 기본 작업 외에 부가적으로 발생하는 비용을 의미합니다. 
- 해결
	- 스레드(thread)
		- 프로세스 내에서 실행되는 정량의 실행 단위로, 같은 프로세스 내에 자원을 공유할 수 있습니다. 

### 프로세스의 종료 
- 프로세스 실행 중 특정 조건을 충족하거나 예기치 않은 문제가 발생하면 종료합니다. 
- 프로세스의 termination는 시스템 자원을 효율적으로 사용하고 안정성을 유지하는데 매우 중요 
- 종료한 프로세스의 자원 회수와 상태 관리는 운영체제가 담당 
	- 자원 회수
		- 운영체제는 종료된 프로세스가 점유하고 있던 메모리, 파일 디스크립터, CPU 자원 등을 해제해 다른 프로세스가 사용토록 합니다. 
	- PCB제거 
		- 운영체제는 종료한 프로세스의 PCB를 메모리서 제거 
	- 종료 상태 관리 
		- 운영체제는 종료한 프로세스의 상태를 기록하고, 필요에 따라 부모 프로세스에 종료 코드를 전달 

### 프로세스 종료 유형 
- **정상 종료**
	- 프로세스에 할당된 모든 작업을 정상적으로 종료한 경우 
	- 이때 일반적으로 종료 코드 0을 반환 
- **요청에 의한 종료**
	- 사용자 또는 운영체제의 요청으로 프로세스를 강제 종료하는 경우 
	- 사용자는 윈도우의 작업 관리자 또는 UNIX/LINUX의 kill명령어를 통해 프로세스 종료 가능 
	- 강제 종료 사유
		- 메모리 부족 
		- 우선순위 정책 
		- 비정상적인 동작 감지 
- **비정상 종료**
	- 오류 또는 예기치 않은 문제가 발생해 프로세스가 강제 종료되는 경우 
	- 원인들 
		- segmentation fault(메모리 접근 오류)
		- invalid pointer access(잘못된 메모리 참조)
		- 파일 디스크립터 초과 
		- 비정상적인 종료 신호(SIGKILL, SIGTERM)
			- 이 경우 종료 코드는 0이 아닌 값(1, -1, 2등)반환이 일반적 
### 자식 프로세스의 종료 
- 자식 프로세스가 종료되면 운영체제는 자식 프로세스의 PPID를 참조해 해당 부모 프로세스에 종료 신호를 보냅니다. 
- 윈도우에서는 부모 프로세스가 특정 API를 사용해 자식 프로세스의 종료 감지 
- 유닉와 리눅스 계열에서는 부모 프로세스가 wait(), waitpid() 시스템 호출을 사용해 자식 프로세스의 종료 상태를 확인하고 자원을 해제

### 고아 프로세스와 좀비 프로세스 
- Orphan Process
	- 부모 프로세스가 종료되어 그 부모의 모든 자식 프로세스는 고아 프로세스가 됩니다.
	- 고아 프로세스는 더 이상 부모 프로세스의 관리와 자원 헤제를 받을 수 없음 
	- 해결책 
		- 운영체제는 고아 프로세스를 다른 상위 프로세스 또는 초기 프로세스에 인계해 관리 
		- 원도우에서는 부모 프로세스가 종료될 경우 자식 프로세스도 자동 종료되는 경우가 많음 
		- 유닉스와 리눅스 계열에서는 init or systemd가 고아 프로세스를 관리 
- Zombie Process
	- 이미 종료된 프로세스지만, 운영체제의 메모리에 PCB가 남아 있는 상태 
	- 이로 인해 운영체제의 자원을 차지하게 되어 성능 저하를 유발할 수 있음 
	- 해결책 
		- 부모 프로세스에서 wait(), waitpid()시스템 호출을 사용해 종료 상태를 수집 
		- 부모 프로세스가 종료될 경우 자동으로 운영체제가 좀비 프로세스를 정리토록 함 
			- 리눅스에서는 init process가 이러한 좀비 프로세스를 정리하는 역할을 수행 

## 프로세스 간 통신 
- 멀티프로세스 환경에서는 각 프로세스가 독립적인 메모리 공간을 사용하므로 직접 데이터를 공유할 수 없습니다. 
	- 이를 해결하기 위해 프로세스 간 통신이 등장 
- 프로세스 간 통신(IPC, Inter-Process Communication)
	- 프로세스들이 서로 데이터를 주고받으며 상호작용할 수 있게 하는 방법 
	- os는 IPC를 통해 여러 프로세스가 데이터를 공유하고, 자원을 협력적으로 사용할 수 있도록 관리 

### 파이프(Pipe)
- 두 프로세스 간 데이터를 주고받을 수 있는 통신 채널로, 먼저 쓴 데이터를 먼저 읽는 FIFO구조로 작동합니다. 
	- 한 프로세스가 파이프에 데이터를 쓰면 다른 프로세스가 이를 읽을 수 있습니다. 
	- 파이프는 기본적으로 한 방향으로만 데이터 전송이 가능한 단방향 통신입니다. 
	- 만약, 양방향 통신을 하려면 파이프가 2개를 사용해야 합니다. 
- 파이프 종류
	- **익명 파이프(anonymous pipe)**
		- 이름이 없는 단방향 통신 채널로, 주로 부모 프로세스와 자식 프로세스 간 통신에서 사용 
		- 파일 시스템에서 직접 접근할 수 없고, 파일 디스크립터를 통해 접근합니다. 
		- 사용법 
			- pipi() 시스템 호출을 사용해 생성하고, 해당 파이프를 생성한 프로세스가 종료되면 파이프도 사라집니다. 
	- **명명된 파이프(named pipe)**
		- 이름이 있는 특수한 파일 형태의 양방향 통신입니다. 
		- 서로 관계없는 프로세스간에도 통신할 수 있습니다. 
		- 파일 시스템에 존재하므로 여러 프로세스가 해당 파이프 파일을 사용해 접근 가능 
		- 운영체제가 재부팅되거나 프로세스가 종료되더라도 파이프 파일은 유지 
		- 사용법 
			- mkfifo 명령어 또는 mkfifo()시스템 호출을 통해 파이프 파일을 생성 
### 메시지 큐
- 프로세스가 직접 데이터를 공유하지 않고, 운영체제에서 관리하는 큐를 사용해 프로세스들이 메시지를 주고받는 방식입니다. 
- FIFO구조로 작동, 일부 시스템에서는 메시지 우선순위를 설정 가능 
- 메시지 구성
	- 데이터
	- 메타데이터(발신자, 수신자, 메시지 타입, 우선순위 등)
- 운영체제는 각 메시지를 고유한 ID로 식별해 관리합니다. 
- 메시지 큐 작동 방식 
	1. 송신 프로세스가 메시지를 메시지 큐에 추가(enqueue)합니다.
	2. 운영체제가 메시지를 저장하고 대기 상태로 유지 
	3. 수신 프로세스가 메시지를 큐에서 가져가서(dequeue)처리
	4. 처리한 메시지는 큐에서 삭제합니다. 
### 공유 메모리(shared memory)
- 여러 프로세스가 특정 메모리 공간을 공유해 데이터를 주고받는 방식 
- 운영체제의 개입 없이 프로세스들이 메모리를 직접 읽고 쓸 수 있으므로 가장 빠른 IPC방식 
- 공유메모리 작동 과정 
	1. 한 프로세스가 운영체제에 공유 메모리 생성을 요청 
	2. 운영체제는 공유 메모리의 식별자(ID)를 만들고 크기 및 접근 권한을 설정 
	3. 다른 프로세스는 해당 ID로 공유 메모리에 접근을 요청 
	4. 운영체제는 접근 권한을 확인한 후 허용 
	5. 프로세스가 데이터를 공유 메모리에 읽고 씁니다. 
	6. 공유 메모리가 필요 없어지면 운영체제가 메모리를 회수해 다른 프로세스가 사용할 수 있게 합니다. 

### 소켓(Socket)
- 네트워크를 통해 프로세스들이 데이터를 주고받는 방식, 양방향 방식을 지원 
- 소켓의 작동 방식 
	1. 서버가 소켓을 생성하고 클라이언트 요청을 대기합니다. 
	2. 클라이언트가 서버에 접속을 요청 
	3. 서버가 요청을 수락해 연결을 형성 
	4. 양쪽에서 데이터를 송수신 
	5. 통신이 끝나면 소켓을 닫습니다. 

### 시그널(signal)
- 특정 이벤트나 프로세스의 상태 변화를 알리는데 사용하는 방법입니다. 
- 복잡한 데이터가 아닌 간단한 메시지를 전달합니다. 
- 시그널은 비동기적으로 전달되므로 시그널이 발생하면 수신 프로세스는 현재 실행 중인 코드와 관계없이 즉시 시그널을 받을 수 있습니다. 
- **시그널의 역할**
	- 특정 프로세스를 제어하는 지시를 내릴 수 있습니다. 
## 스레드(Thread)
- 프로세스 내에서 실행되는 작은 실행 단위로, 하나의 프로세스는 여러 스레드를 가질 수 있습니다. 
- **멀티스레드(multithread)**
	- 한 프로세스에서 여러 스레드가 동시에 실행되는 것을 의미합니다. 
	- 멀티스레드를 사용하면 한 프로세스 내에서 여러 작업을 동시에 수행 가능합니다. 
- 스레드는 같은 메모리 공간을 공유하면서 독립적으로 실행 
- 코드, 데이터, 힙영역은 모든 스레드가 공유하지만, 스택 영역은 각 스레드에 개별적으로 존재해 독립적인 실행 흐름을 유지 
- **스레드 제어 블록(TCB, Thread Control Block)
	- 각 스레드의 상태와 실행 정보를 저장하는 데이터 구조 
	- 운영체제 커널이 이를 관리해 스레드를 스케줄링하고 실행 상태를 유지 
	- TCB는 프로세스의 PCB와 연결되어 있어 스레드와 프로세스 간 관계를 관리 
### 멀티스레드에서 컨텍스트 스위칭과 동기화 문제 
- 스레드도 실행 중 스케줄러에 의해 다른 스레드로 전환될 때 컨텍스트 스위칭이 발생 
- 컨텍스트 스위칭이 발생하면 운영체제는 현재 실행 중인 스레드의 정보를 TCB에 저장, 새로 실행한 스레드의 TCB정보를 로드해 실행을 재개 
- **컨텍스트 스위칭 문제**
	- 비용이 발생하는 작업이므로 빈번한 전환을 최소화하는 것이 중요 
	- 스레드 개수를 최적화하고, 스케줄링을 조정하는 것이 성능 향상에 중요 
- **동기화 문제**
	- 멀티스레드 환경에서는 여러 스레드가 메모리를 공유하기 때문에 한 스레드에서 수정한 메모리의 내용이 다른 스레드에 영향을 미칠 수 있습니다. 
- 스레드 개수를 적절하게 선택하지 않으면 운영체제의 자원 사용이 늘어나고, 성능이 저하될 수 있습니다.
