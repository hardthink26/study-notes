## 파일 시스템 개요 
- 파일 시스템은 컴퓨터에서 데이터를 저장하고 관리하는 방법을 정의한 시스템입니다. 
- 파일 시스템은 파일(문서, 이미지, 비디오, 프로그램 등)을 저장하며, 사용자가 파일에 쉽게 접근할 수 있도록 합니다. 
## 파일과 메타데이터 
- 파일 시스템은 파일과 메타데이터를 저장하고 관리합니다. 
### 파일 
- 컴퓨터에서 데이터를 저장하고 관리하는 기본 단위입니다. 
- 파일에는 다양한 형태의 정보를 담을 수 있습니다. 
	- 텍스트/문서 파일 
		- 일반 텍스트나 문서를 저장합니다. 
		- .txt, .docs, .pdf ... 
	- 이미지 파일 
		- 사진이나 그림을 저장 
		- .jpg, .png, .gif
	- 비디오 파일 
		- 동영상을 저장 
		- .mp4, .avi, .mkv
	- 오디오 파일 
		- .mp3, .wav, .aac
	- 프로그램 파일 
		- 소프트웨어 실행 파일이나 소스 코드를 포함합니다.
		- .exe, .dll, .py
- **구성**
	- 각 파일은 컴퓨터에서 고유한 이름과 형식을 가짐 이를 **파일 이름** 과 **파일 확장자** 라고 합니다. 
		- 확장자는 작업의 유형을 나타내며, 운영체제는 이를 기반으로 해당 파일을 처리하기에 적합한 프로그램을 연결합니다. 
- 파일은 컴퓨터의 보조 기억 장치(HHD, SSD, USB 드라이버 등)에 저장하고, 파일 시스템이 이를 관리합니다. 
### 메타데이터 
- 파일 자체가 아닌 파일에 대한 추가 정보를 담고 있는 데이터입니다. 
- 파일이 어떤 것인지 설명해 주는 정보 
- **구성 요소**
	- 사용자 ID
		- 파일을 만든 사람이나 사용자 정보 
	- 파일 유형 
		- 파일의 형식(문서, 이미지, 음악 등)
	- 파일 크기 
		- 파일이 차지하는 용량 
	- 저장 위치 
		- 파일을 저장하는 경로 
	- 오프셋 정보 
		- 파일 내 데이터의 위치 
	- 버퍼 정보 
		- 데이터를 임시로 저장한 공간에 대한 정보 
	- 시간 정보 
		- 파일의 생성(수정/접근 시간)
- 메타데이터를 파일 시스템에 파일과 별도로 
- 파일 시스템은 메타데이터를 기반으로 파일의 위치와 속성을 관리합니다. 

## 디렉터리와 경로 

### 디렉터리 
- 파일을 체계적으로 그룹화해 관리하는 논리적인 구조입니다. 
- 디렉터리 안에 같은 이름을 가진 하위 디렉터리는 존재할 수 없습니다. 
- **구조**
	- 트리 구조를 기반으로 계층적으로 구성
	- 최상위 디렉터리는 루트 디렉터리로, 모든 파일과 디렉터리의 시작점입니다. 
	- 루트 디렉터리에는 여러 하위 디렉터리(subdirectory)에 파일을 포함 가능 
	- [[구조 그림 넣기 ]]
- 파일 시스템은 디렉터리와 파일을 계층적으로 관리합니다. 
	- 이러한 계층 구조는 사용자가 파일이나 디렉터리를 체계적으로 관리하고 필요한 데이터를 빠르게 탐색 가능하게 합니다. 
### 경로 
- 디렉터리 안 하위 디렉터리의 파일은 특정 경로를 통해 접근할 수 있습니다. 
- 경로는 특정 파일이나 디렉터리의 위치를 나타냅니다. 
- **경로의 형태**
	- **절대 경로(absolute path)**
		- 루트 디렉터리부터 시작해 특정 파일이나 디렉터리까지의 전체 경로를 나타냅니다. 
		- 항상 고유하며, 경로의 위치를 명확히 지정해야 합니다. 
	- **상대 경로(relative path)**
		- 현재 디렉터리를 기준으로 파일이나 디렉터리의 위치를 지정하는 방식입니다. 
		- 경로에서 디렉터리를 구분하는 구분자는 운영체제에 따라 다릅니다. 
			- **UNIX계열(리눅스, 맥OS)**: 슬래시 (/)
			- **윈도우**: 백슬래시(\)
## 파일 시스템의 주요 기능 
### 데이터 저장 
- 파일 시스템은 데이터를 보조 기억 장치에 블록 단위로 나누어 저장합니다. 
	- 블록은 데이터를 저장하는 기본 단위이며, 파일의 크기에 따라 여러 블록으로 나누어 저장 가능
- 파일 시스템은 보조 기억 장치의 특성에 맞춰 데이터를 효율적으로 배치해 읽기 및 쓰기 성능을 극대화
### 데이터 검색 
- 파일 시스템은 파일을 쉽게 찾을 수 있도록 인덱싱과 매핑 기능을 제공합니다. 
- 파일은 파일 이름, 경로, 메타데이터를 기반으로 검색할 수 있습니다. 
- 운영체제는 파일 시스템의 인덱스(목록)를 사용해 해당 파일을 저장한 블록 위치를 빠르게 찾아냅니다. 
### 접근 제어 
- 파일과 디렉터리는 읽기, 쓰기, 실행 권한을 가질 수 있습니다. 
- 이러한 권한은 사용자 또는 그룹에 따라 제한 가능 
### 보안 
- 파일 시스템은 파일을 암호하해 데이터를 보호하고, 무단 접근을 방지합니다. 
### 데이터 무결성
- 파일이 손상되지 않고 원래 상태를 유지하는 것을 의미합니다. 
- 파일 시스템ㅁ은 데이터를 저장할 때 체크섬 또는 해시 값을 생성해 나중에 파일을 읽을 때 데이터가 변형되지 않았는지 검증 
	- **체크섬(checksum)**
		- 파일의 특정 계산값을 저장해 파일이 손상되었을 경우 이를 감지하는 방법입니다. 
	- **해시값**
		- 파일의 고유한 데이터 서명을 저장해 변조 여부를 확인하는 방법입니다. 
### 데이터 복구 
- 파일 시스템은 작업 로그를 저장해 갑작스러운 오류나 정전이 발생하더라도 데이터 손실을 최소화합니다. 
- 이 기능을 **저널링(journaling)** 이라고 합니다. 
- 또한, 파일 시스템의 특정 시점 상태를 그대로 복사한 **스냅샷(snapshot)** 을 저장해 필요할 때 복구를 할 수 있습니다. 
### 성능 최적화
- 파일 시스템은 성능 최적화를 위해 캐싱, 버퍼링, 디스크 조각 모음을 수행합니다. 
	- **캐싱**
		- 자주 사용하는 데이터를 메모리에 저장해 접근 속도를 높이는 방법입니다. 
	- **버퍼링**
		- 파일을 보조 기억 장치에 저장하기 전에 먼저 메모리에서 임시로 처리하는 버퍼링을 사용해 성능을 높일 수 있습니다. 
		- 버퍼링을 활용하면 작은 파일을 여러 번 저장하는 대신 한 번에 모아서 저장해 효율성을 증가시킵니다. 
	- **디스크 조각 모음(defragmentation)**
		- 파일을 저장할 때 연속한 블록에 배치하면 디스크 조각화를 줄일 수 있습니다. 
			- 디스크 조각화는 파일이 여러 블록에 나뉘어 저장하는 현상입니다. 
		- 디스크 조각 모음 도구를 사용해 데이터를 다시 정리합니다.
- 파일 시스템은 단순히 파일을 저장하는 역할을 하는 것이 아니라 운영체제와 응용 프로그램이 데이터를 저장하고 접근하는 핵심 기술입니다. 

## 파일 시스템의 종류
- 파일 시스템은 다양한 운영체제와 환경에서 데이터를 저장하고 관리하기 위해 만들어졌습니다. 
### FAT(File Allocation Table)
- 가장 오래된 파일 시스템으로, 구조가 단순해서 여러 운영체제와 장치에서 널리 쓰입니다. 
	- FAT는 파일을 저장할 공간을 파일 할당 테이블로 관리하고, 파일을 저장한 위치와 연결된 블록 정보를 기록합니다. 
### NTFS(New Technology File System)
- MS에서 윈도우 운영체제를 위해 개발한 파일 시스템입니다. 
- 최대 16EB(엑사바이트)크기의 파일과 드라이버를 지원하며, 파일 정보와 메타데이터를 저장하는 특수한 인덱스 구조를 사용합니다. 
- 파일과 디렉터리에 세부적인 접근 권한을 설정할 수 있고, 파일을 압축해 저장 공간을 절약 가능
- 보안을 위해 파일을 암호화하며, 변경 사항을 기록해 시스템 장애 발생 시 데이터 손실을 방지합니다. 
### ext(Extended File System)
- 리눅스 운영체제를 위해 설계한 파일 시스템으로, 파일 크기와 디스크 크기에 대한 제한이 적어 대용량 저장 장치에서도 안정적으로 작동합니다. 
### HFS& APFS
- HFS(Hierarchical File System)
	- 맥에서 사용하던 오래된 파일 시스템입니다. HDD에 최적화되어 SSD와 같은 최신 보조 기억 장치의 성능을 충분히 사용하지 못하고, 스냅샷 같은 보안 기능이 부족합니다. 
	- 따라서 APFS로 대체되었습니다. 
- APFS(Apple File System)
	- 최신 맥OS, iOS device에서 사용하는 파일 시스템입니다. 
	- SSD에 최적화되어 빠른 속도를 제공합니다. 
	- 스냅샷 기능을 지원해 특정 시점의 데이터를 빠르게 복구할 수 있습니다. 
	- 또한, 파일을 복제할 때 저장 공간을 최소화해 더 빠르고 효율적으로 작동합니다. 

## 파일 시스템의 구조 
- 파일 시스템은 데이터를 저장하고 관리하는 데 중요한 역할을 합니다. 
### 파일 시스템의 저장 구조 
- 파일 시스템은 데이터를 효율적으로 저장하고 관리하기 위해 여러 단계로 나뉩니다. 
	- **디스크**
		- HDD, SSD와 같은 물리적 저장 장치로, 파일 시스템이 데이터를 저장하는 기본 장치입니다. 
	- **파티션**
		- 하나의 디스크를 여러 개의 독립적인 영역으로 나누는 것으로, 파티션마다 별도의 파일 시스템을 가질 수 있습니다. 
	- **볼륨**
		- 파일 시스템을 적용한 논리적 저장 공간입니다. 
		- 하나의 파티션이 하나의 볼륨이 될 수 있지만, 여러 파티션을 묶어 하나의 볼륨을 구성할 수 있습니다. 
		- 볼륨에 이름을 부여하면 운영체제는 이를 드라이브(drive)라고 인식합니다. 
	- **파일 시스템**
		- 볼륨 내에서 데이터를 저장하고 관리하는 구조로, 데이터를 파일과 디렉터리 형태로 구성합니다. 
	- **디렉터리**
		- 파일을 그룹화해 정리하는 구조입니다. 
		- 다른 디렉터리를 포함할 수 있으며, 트리 구조를 형성해 파일을 관리합니다. 
	- **파일**
		- 데이터를 저장하는 기본 단위로, 텍스트, 이미지, 비디오 등 다양한 형식이 있습니다. 
		- 4, 8KB등 고정 크기를 사용해 데이터를 저장 
	- **데이터 블록(data block)**
		- 실제 데이터를 저장하는 블록 
		- 파일 크기에 따라 여러 데이터 블록을 사용할 수 있습니다. 
- 상위 계층은 디스크, 파티션, 볼륨을 관리하는 부분으로, 데이터를 물리적으로 저장하는 장치(HHD, SSD)의 공간을 관리합니다. 
	- 파일 시스템을 운영하고, 저장 공간을 논리적으로 분할해 정리하며, 운영체제가 데이터를 어디에 저장할지 결정하고 , 파일을 효율적으로 배치합니다. 
- 하위 계층은 파일과 디렉터리를 관리하는 부분으로, 파일을 저장하고 이름을 부여하여 크기, 위치, 속성 등의 정보를 관리합니다. 
	- 또한, 파일을 읽고 쓰는 기능을 제공하며 파일 간 관계를 정리해 사용자가 파일을 쉽게 찾고, 관리할 수 있도록 계층적 구조를 제공합니다. 
## 물리적 저장소와 논리적 구조 
- 파일 시스템은 물리적 저장소(HDD, SSD)에 데이터를 저장하지만, 사용자는 논리적 구조(파일과 디렉터리)를 통해 데이터를 쉽게 찾고 관리 가능합니다. 
- **물리적 저장소**
	- 데이터를 실제로 저장하는 하드웨어 장치입니다. 
	- 데이터는 전원이 꺼져도 사라지지 않으며, 물리적 주소로 접근 가능합니다. 
- **논리적 구조**
	- 사용자가 데이터를 쉽게 탐색하고 관리할 수 있도록 설계한 가상의 구조입니다. 
- 사용자가 논리적 주소(파일 경로)로 파일을 요청하면 운영체제가 이를 물리적 주소(블록 위치)로 반환하는 과정을 수행합니다. 
## 데이터 블록과 인덱스 구조 
### 데이터 블록이란
- 파일 데이터를 실제로 저장하는 기본 단위입니다. 블록 크기는 파일 시스템마다 다르며, 일반적으로 4,8, 16KB 등으로 설정합니다. 
- 파일 시스템은 어떤 블록이 사용 중이고, 어떤 블록이 비어 있는지를 추적해야 합니다. 
	- **비트맵(bitmap)**
		- 각 블록의 상태를 0또는 1로 저장해 관리하는 방법입니다. 
		- 0은 빈 블록(사용가능)이고 1은 사용 중인 블록입니다. 
		- 빠르게 블록 상태를 확인할 수 있지만 블록이 많아질수록 비트맵 크기가 커질 수 있습니다. 
	- **빈 블록 리스트(free block list)**
		- 사용 가능한 블록 목록을 따로 저장해 관리하는 방법입니다. 
		- 파일 시스템이 새로운 데이터를 저장할 때 빈 블록 리스트에서 사용 가능한 블록을 할당합니다. 
		- 필요한 블록을 쉽게 할당할 수 있지만 관리해야 할 리스트가 커질 수 있습니다. 
### 데이터 블록 할당 방식 
- 파일을 저장할 데이터 블록을 어떻게 선택하고 관리하는지를 정의합니다. 
- 일반적인 할당 방식에는 연속 할당, 연결 할당, 인덱스 할당 등이 있습니다. 
	- **연속 할당(contiguous allocation)**
		- 파일 데이터를 디스크의 연속한 블록에 저장하는 방식입니다. 
		- 이 방식은 파일을 저장할 때 필요한 크기만큼 연속 공간을 미리 확보합니다. 
		- **장점**
			- 파일을 읽고 쓸 때 디스크 헤드가 순차적으로 이동하므로 접근 속도가 매우 빠릅니다. 
			- 파일의 시작 위치(블록 번호)와 크기만 저장하면 되므로 파일 관리가 간단하고, 헤드 이동을 최소화해 성능을 향상시킵니다. 
		- **단점**
			- 새로운 파일을 저장하려할 때 기존 파일이 삭제되어 비어 있는 공간이 중간중간 생기면 큰 파일을 저장할 공간이 부족할 수 있습니다. 
				- 조각화가 심해지면 디스크 공간을 비효율적으로 사용하게 됩니다. 
			- 파일이 커지면 기존에 할당한 연속 공간이 부족할 경우 다른 큰 공간으로 옯겨야 합니다. 
				- 이 과정에서 파일 이동(재배치)시간을 추가로 소요합니다. 
	- **연결 할당(linked allocation)**
		- 파일 데이터를 연속 공간이 아닌 임의 블록에 저장하고 각 블록에 다음 블록의 주소를 포함하는 방식입니다. 
			- 파일의 첫 번째 블록 주소만 알고 있으면 이후 블록들을 따라가면서 데이터를 읽을 수 있습니다. 
		- **장점**
			- 파일을 저장할 때 디스크의 빈 블록 아무 곳이나 사용할 수 있어서 조각화를 최소화할 수 있습니다. 
			- 새로운 블록을 쉽게 추가할 수 있어서 파일 크기 중간에 유연하게 대응할 수 있으며 빈 공간을 효율적으로 사용할 수 있어 디스크 활용도가 높습니다. 
		- **단점**
			- 각 블록에 파일 데이터뿐 아니라 다음 블록의 주소를 저장할 공간이 필요하고, 포인터 크기(4바이트, 8바이트 등)커질수록 디스크 공간에 낭비가 발생할 수 있습니다. 
			- 만약 포인터 정보가 깨지면 해당 블록 이후의 데이터를 찾을 수 없어 파일이 손상될 위험이 있습니다. 
			- 특정 데이터 블록에 바로 접근할 수 없으며, 처음부터 순차적으로 탐색해야 합니다. 
	- **인덱스 할당(index allocation)**
		- 파일을 구성하는 모든 데이터 블록의 주소를 별도의 인덱스 블록에 저장하는 방식입니다. 
			- 이 방식은 파일마다 인덱스 블록을 하나씩 생성해 파일을 저장한 모든 데이터 블록의 위치(주소)를 저장합니다. 
		- **장점**
			- 데이터 블록이 디스크 전체에 흩어져 있어도 인덱스 블록을 사용해 원하는 블록에 바로 접근할 수 있습니다. 
			- 새로운 데이터가 추가되면 인덱스 블록에 새로운 블록의 주소만 추가하면 되기 때문에 파일을 확장하기 쉽습니다. 
		- **단점**
			- 데이터 블록 외에 추가로 인덱스 블록을 저장하고 관리해야 하는 부담이 생깁니다. 
			- 작은 파일이 많을 경우 인덱스 블록의 공간 낭비가 발생할 수도 있습니다. 
		- 이외에도 데이터 블록을 다단계 인덱스로 관리하는 멀티레벨 인덱스 할당(multi-level indexed allocation), 파일을 연속된 블록 묶음(extent)으로 저장하는 확장 할당(extent allocation)방식이 있습니다. 
### 인덱스 구조 
- 파일의 데이터 블록에 대한 정보를 저장하는 방법을 정의합니다. 
- 인덱스 구조를 활용하면 전체 데이터를 순차적으로 검색하지 않고도, 원하는 파일이나 데이터 블록을 빠르게 찾을 수 있습니다. 
- **FAT(File Allocation Table)**
	- 파일의 데이터 블록이 연속해서 저장되지 않을 때 이를 관리하기 위한 테이블입니다. 
	- 각 블록의 상태와 다음 블록의 위치를 기록합니다. 
	- 연결될 블록들로 파일을 구성하므로 특정 블록에 접근하려면 처음부터 순차적으로 검색해야 해서 접근 속도가 느립니다. 
- **inode(아이노드)**
	- 유닉스 및 리눅스 기반 파일 시스템에서 사용되는 데이터 구조로, 파일의 메타데이터와 데이터 블록 정보를 저장합니다. 
	- 각 파일은 고유한 아이노드 번호를 가지며 이 번호를 통해 해당 파일의 메타데이터에 접근합니다. 
		- 메타데이터는 아이노드 블록에 저장되며, 이 블록은 파일 시스템의 특정 영역에 위치합니다. 
		- 데이터 블록의 위치는 아이노드가 가리키는 블록 번호로 저장됩니다. 
- **B-Tree**
	- 균형 잡힌 트리 구조로, 각 노드는 여러 개의 키(값)와 자식 노드(포인터)를 가질 수 있습니다. 
	- 데이터를 정렬한 상태로 저장하며 검색, 삽입, 삭제가 빠릅니다. 
	- 파일 위치를 트리로 저장해 데이터가 많아도 성능이 급격히 저하되지 않습니다. 
## 파일 시스템의 작동원리 
- 파일 시스템은 데이터를 효율적으로 저장, 검색, 보호, 최적화하기 위해 다양한 메커니즘을 이용하며, 안정적이고 신뢰성 있는 데이터 관리를 제공합니다. 
- 파일 시스템은 파일을 읽고 쓰는 과정에서 데이터를 효율적으로 배치하고 검색하는 역할을 수행 
- 이를 위해 메타데이터 관리, 데이터 블록 할당 방식, 읽기/쓰기 최적화 기술 등을 활용 
### 파일 읽기 및 쓰기 과정 
- 파일 시스템은 파일을 디스크에 저장하고, 필요할 때 빠르게 검색하는 기능을 수행합니다. 
- **파일 읽기**
	- 읽기 과정
		1. 파일 접근 요청
			- 사용자가 파일을 열면 운영체제가 파일 시스템에 요청을 보냅니다. 
		2. 메타데이터 참조 
			- 파일 시스템이 메타데이터에서 해당 파일이 저장된 위치를 찾습니다. 
		3. 데이터 블록 식별
			- 파일이 저장된 블록의 물리적 위치를 확인합니다. 
		4. 디스크에서 데이터 읽기 
			- 디스크에서 해당 블록을 읽어옵니다. 
		5. 데이터 전달
			- 읽어온 데이터를 요청한 사용자 프로그램에 전달합니다. 
- **파일 쓰기**
	- 파일 저장 과정은 사용자가 파일을 만들거나 데이터를 저장할 때 일어납니다. 
	- 쓰기 과정
		1. 파일 생성 요청
			- 사용자가 파일을 생성하면 운영체제가 파일 시스템에 파일 생성 요청을 보냅니다. 
		2. 빈 블록 할당 
			- 파일 시스템은 디스크에서 빈 블록을 찾아 파일 크기에 맞게 할당
		3. 메타데이터 생성 
			- 파일 이름, 크기, 생성 날짜 같은 정보를 포함하는 메타데이터를 생성 
		4. 블록 매칭
			- 아이노드 또는 디렉터리 엔트리를 사용해 사용자 파일과 데이터 블록을 연결 
		5. 데이터 기록 
			- 파일 데이터를 블록에 저장합니다. 저장을 완료하면 이를 사용자에게 알립니다. 
- **파일 읽기 및 쓰기 최적화**
	- 파일 시스템은 디스크 접근 속도를 높이고, 쓰기 성능을 향상하기 위해 다양한 최적화 기법을 사용합니다. 
		- **프리페칭(pre-fetching)**
			-
