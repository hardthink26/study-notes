# 4. 스케줄링

스케줄링은 여러 작업이 같은 자원을 필요로 할 때 **어떤 작업에 자원을 먼저 할당할지** 정하는 방식이다. CPU 스케줄링은 준비 큐에서 다음에 실행할 프로세스를 고르고, 입출력 스케줄링은 디스크 같은 장치가 처리할 요청 순서를 정한다.

## 설계 목표와 시간 지표

- **공정성과 예측 가능성**: 실행 기회가 한쪽에 몰리지 않도록 하고 지연의 변동을 줄인다.
- **CPU 이용률과 처리량**: 실행할 작업이 있을 때 CPU의 유휴 시간을 줄이고, 단위 시간당 완료하는 작업 수를 늘린다.
- **응답 속도와 기한**: 대화형 작업은 첫 응답을 빠르게 하고, 실시간 작업은 정해진 기한을 만족하도록 스케줄링한다.

| 지표 | 의미 |
| --- | --- |
| 도착 시간 (arrival time) | 예제에서 프로세스가 처음 준비 큐에 들어온 시각 |
| CPU 버스트 (CPU burst) | 종료되거나 입출력을 기다리기 전까지 연속해서 요구하는 CPU 실행 시간. 선점되면 여러 구간에 나뉘어 실행될 수 있다. |
| 응답 시간 (response time) | 처음 CPU를 할당받은 시각 − 도착 시각 |
| 대기 시간 (waiting time) | 준비 큐에서 CPU 할당을 기다린 시간의 합 |
| 반환 시간 (turnaround time) | 작업 완료 시각 − 도착 시각 |

## 선점형과 비선점형

| 구분 | 실행 중인 프로세스가 CPU를 내놓는 시점 | 고려할 점 |
| --- | --- | --- |
| 선점형 (preemptive) | 시간 할당량이 끝나거나 정책상 더 우선하는 작업이 준비되면, 운영체제가 실행 중인 프로세스를 중단할 수 있다. | 새 작업에 빠르게 반응할 수 있지만, 전환이 잦으면 컨텍스트 스위칭 비용이 커진다. |
| 비선점형 (nonpreemptive) | 실행 중인 프로세스가 종료하거나, 입출력 대기 등으로 실행할 수 없게 되거나, 스스로 CPU를 양보할 때 교체한다. | 강제 교체 비용은 줄지만, 긴 CPU 버스트 뒤에 짧은 작업이 대기할 수 있다. |

입출력을 기다리기 시작한 프로세스는 **실행 → 대기** 상태로 이동한다. 선점된 프로세스는 여전히 실행할 수 있으므로 **실행 → 준비** 상태로 돌아간다.

## CPU 스케줄링 알고리즘 비교

| 알고리즘 | 다음 작업의 선택 기준 | 선점 여부 |
| --- | --- | --- |
| FCFS (FIFO) | 준비 큐에 먼저 들어온 작업 | 비선점형 |
| SJF | 다음 CPU 버스트가 가장 짧은 작업 | 비선점형 |
| SRT (SRTF, SRTN) | 남은 CPU 버스트가 가장 짧은 작업 | 선점형 |
| RR | 준비 큐의 맨 앞 작업을 최대 한 시간 할당량 동안 실행 | 선점형 |
| 우선순위 스케줄링 | 우선순위가 가장 높은 작업 | 정책에 따라 둘 다 가능 |
| EDF | 완료 기한이 가장 가까운 작업 | 대표적으로 선점형으로 사용 |

### FCFS와 라운드 로빈

- **FCFS (First-Come, First-Served)**는 먼저 도착한 작업부터 실행한다. 구현이 단순하고 타이머에 의한 강제 교체가 없어 배치 작업에 적용하기 쉽다. 긴 작업이 먼저 오면 뒤의 짧은 작업들이 함께 기다리는 **호송 효과(convoy effect)**가 생길 수 있다.
- **라운드 로빈(RR, Round Robin)**은 준비 큐의 맨 앞 작업에 **시간 할당량(time quantum)**을 준다. 시간 안에 끝나거나 입출력 대기로 들어가면 다음 작업을 실행한다. 할당량이 끝났는데 계속 실행할 수 있다면 큐의 맨 뒤로 보낸다.
- RR의 할당량이 짧으면 각 작업에 차례가 빨리 돌아오지만 전환 비용이 커진다. 할당량이 길면 전환은 줄고 뒤의 작업은 더 오래 기다릴 수 있다.

### SJF와 SRT

- **SJF (Shortest Job First)**는 CPU가 비었을 때 준비 큐에서 다음 CPU 버스트가 가장 짧은 작업을 고른다. 실행을 시작한 작업은 짧은 작업이 도착해도 계속 실행한다.
- **SRT (Shortest Remaining Time)**는 SJF의 선점형 방식이다. 새 작업의 버스트가 현재 작업의 **남은 시간**보다 짧으면 선점한다. 선점된 작업은 준비 큐로 돌아가며, 이후에도 남은 시간을 기준으로 선택된다.
- **예시**: A가 시각 0에 도착해 CPU 시간 8을 요구하고, B가 시각 2에 도착해 CPU 시간 3을 요구한다. 시각 2에 A는 6이 남는다. SJF는 A를 시각 8까지 실행하고, SRT는 B를 시각 2부터 5까지 실행한 뒤 A를 재개한다.
- 짧은 작업을 우선하면 평균 대기 시간을 줄이는 데 유리하다. 다만 실제 CPU 버스트는 미리 추정해야 하고, 짧은 작업이 계속 들어오면 긴 작업은 **기아(starvation)**에 빠질 수 있다.

### 우선순위 스케줄링과 에이징

우선순위가 가장 높은 준비 작업을 먼저 실행한다. 동점이면 FCFS 같은 규칙으로 다음 작업을 고를 수 있다. 선점형은 더 높은 우선순위의 작업이 준비되면 교체하고, 비선점형은 현재 작업이 CPU를 놓을 때까지 기다린다.

| 우선순위 방식 | 동작 | 고려할 점 |
| --- | --- | --- |
| 정적 우선순위 | 실행 중에도 처음 정한 우선순위를 유지한다. | 순서가 예측하기 쉽지만 낮은 우선순위의 작업이 계속 밀릴 수 있다. |
| 동적 우선순위 | 대기 시간이나 시스템 상황에 따라 우선순위를 갱신한다. | 상황 변화에 대응할 수 있고, 우선순위를 갱신하는 비용이 든다. |

**에이징(aging)**은 오래 기다린 작업의 우선순위를 점진적으로 높여 기아를 완화하는 방법이다.

### 기한부 스케줄링과 EDF

**기한(deadline)**은 작업을 끝내야 하는 시각이다. 실시간 시스템에서 사용하는 **EDF (Earliest Deadline First)**는 준비된 작업 중 완료 기한이 가장 이른 작업을 선택한다. 선점형 EDF에서는 기한이 더 이른 작업이 도착하면 실행 중인 작업을 교체할 수 있다.

예를 들어 A의 기한이 시각 10이고 B의 기한이 시각 6이면, 둘 다 준비됐을 때 EDF는 B를 먼저 고른다. 기한을 모두 만족할 수 있는지는 각 작업의 실행 시간과 도착 시각, 가용한 CPU 시간에도 달려 있다.
