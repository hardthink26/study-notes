# 4. 스케줄링

스케줄링은 여러 작업이 같은 자원을 필요로 할 때 **어떤 작업에 자원을 먼저 할당할지** 정하는 방식이다. CPU 스케줄링은 준비 큐에서 다음에 실행할 프로세스를 고르고, 입출력 스케줄링은 디스크 같은 장치가 처리할 요청 순서를 정한다.

## 설계 목표와 시간 지표

- **공정성과 예측 가능성**: 실행 기회가 한쪽에 몰리지 않도록 하고 지연의 변동을 줄인다.
- **CPU 이용률과 처리량**: 실행할 작업이 있을 때 CPU의 유휴 시간을 줄이고, 단위 시간당 완료하는 작업 수를 늘린다.
- **응답 속도와 기한**: 대화형 작업은 첫 응답을 빠르게 하고, 실시간 작업은 정해진 기한을 만족하도록 스케줄링한다.

| 지표 | 의미 |
| --- | --- |
| 도착 시간 (arrival time) | 예제에서 프로세스가 처음 준비 큐에 들어온 시각 |
| CPU 버스트 (CPU burst) | 종료되거나 입출력을 기다리기 전까지 연속해서 요구하는 CPU 실행 시간. 선점되면 여러 구간에 나뉘어 실행될 수 있다. |
| 응답 시간 (response time) | 처음 CPU를 할당받은 시각 − 도착 시각 |
| 대기 시간 (waiting time) | 준비 큐에서 CPU 할당을 기다린 시간의 합 |
| 반환 시간 (turnaround time) | 작업 완료 시각 − 도착 시각 |

## 선점형과 비선점형

| 구분 | 실행 중인 프로세스가 CPU를 내놓는 시점 | 고려할 점 |
| --- | --- | --- |
| 선점형 (preemptive) | 시간 할당량이 끝나거나 정책상 더 우선하는 작업이 준비되면, 운영체제가 실행 중인 프로세스를 중단할 수 있다. | 새 작업에 빠르게 반응할 수 있지만, 전환이 잦으면 컨텍스트 스위칭 비용이 커진다. |
| 비선점형 (nonpreemptive) | 실행 중인 프로세스가 종료하거나, 입출력 대기 등으로 실행할 수 없게 되거나, 스스로 CPU를 양보할 때 교체한다. | 강제 교체 비용은 줄지만, 긴 CPU 버스트 뒤에 짧은 작업이 대기할 수 있다. |

입출력을 기다리기 시작한 프로세스는 **실행 → 대기** 상태로 이동한다. 선점된 프로세스는 여전히 실행할 수 있으므로 **실행 → 준비** 상태로 돌아간다.

## CPU 스케줄링 알고리즘 비교

| 알고리즘 | 다음 작업의 선택 기준 | 선점 여부 |
| --- | --- | --- |
| FCFS (FIFO) | 준비 큐에 먼저 들어온 작업 | 비선점형 |
| SJF | 다음 CPU 버스트가 가장 짧은 작업 | 비선점형 |
| SRT (SRTF, SRTN) | 남은 CPU 버스트가 가장 짧은 작업 | 선점형 |
| RR | 준비 큐의 맨 앞 작업을 최대 한 시간 할당량 동안 실행 | 선점형 |
| 우선순위 스케줄링 | 우선순위가 가장 높은 작업 | 정책에 따라 둘 다 가능 |
| EDF | 완료 기한이 가장 가까운 작업 | 대표적으로 선점형으로 사용 |

### FCFS와 라운드 로빈

- **FCFS** (First-Come, First-Served)는 먼저 도착한 작업부터 실행한다. 구현이 단순하고 타이머에 의한 강제 교체가 없어 배치 작업에 적용하기 쉽다. 긴 작업이 먼저 오면 뒤의 짧은 작업들이 함께 기다리는 **호송 효과** (convoy effect)가 생길 수 있다.
- **라운드 로빈** (RR, Round Robin)은 준비 큐의 맨 앞 작업에 **시간 할당량** (time quantum)을 준다. 시간 안에 끝나거나 입출력 대기로 들어가면 다음 작업을 실행한다. 할당량이 끝났는데 계속 실행할 수 있다면 큐의 맨 뒤로 보낸다.
- RR의 할당량이 짧으면 각 작업에 차례가 빨리 돌아오지만 전환 비용이 커진다. 할당량이 길면 전환은 줄고 뒤의 작업은 더 오래 기다릴 수 있다.

### SJF와 SRT

- **SJF** (Shortest Job First)는 CPU가 비었을 때 준비 큐에서 다음 CPU 버스트가 가장 짧은 작업을 고른다. 실행을 시작한 작업은 짧은 작업이 도착해도 계속 실행한다.
- **SRT** (Shortest Remaining Time)는 SJF의 선점형 방식이다. 새 작업의 버스트가 현재 작업의 **남은 시간**보다 짧으면 선점한다. 선점된 작업은 준비 큐로 돌아가며, 이후에도 남은 시간을 기준으로 선택된다.
- **예시**: A가 시각 0에 도착해 CPU 시간 8을 요구하고, B가 시각 2에 도착해 CPU 시간 3을 요구한다. 시각 2에 A는 6이 남는다. SJF는 A를 시각 8까지 실행하고, SRT는 B를 시각 2부터 5까지 실행한 뒤 A를 재개한다.
- 짧은 작업을 우선하면 평균 대기 시간을 줄이는 데 유리하다. 다만 실제 CPU 버스트는 미리 추정해야 하고, 짧은 작업이 계속 들어오면 긴 작업은 **기아** (starvation)에 빠질 수 있다.

### 우선순위 스케줄링과 에이징

우선순위가 가장 높은 준비 작업을 먼저 실행한다. 동점이면 FCFS 같은 규칙으로 다음 작업을 고를 수 있다. 선점형은 더 높은 우선순위의 작업이 준비되면 교체하고, 비선점형은 현재 작업이 CPU를 놓을 때까지 기다린다.

| 우선순위 방식 | 동작 | 고려할 점 |
| --- | --- | --- |
| 정적 우선순위 | 실행 중에도 처음 정한 우선순위를 유지한다. | 순서가 예측하기 쉽지만 낮은 우선순위의 작업이 계속 밀릴 수 있다. |
| 동적 우선순위 | 대기 시간이나 시스템 상황에 따라 우선순위를 갱신한다. | 상황 변화에 대응할 수 있고, 우선순위를 갱신하는 비용이 든다. |

**에이징** (aging)은 오래 기다린 작업의 우선순위를 점진적으로 높여 기아를 완화하는 방법이다.

### 기한부 스케줄링과 EDF

**기한** (deadline)은 작업을 끝내야 하는 시각이다. 실시간 시스템에서 사용하는 **EDF** (Earliest Deadline First)는 준비된 작업 중 완료 기한이 가장 이른 작업을 선택한다. 선점형 EDF에서는 기한이 더 이른 작업이 도착하면 실행 중인 작업을 교체할 수 있다.

예를 들어 A의 기한이 시각 10이고 B의 기한이 시각 6이면, 둘 다 준비됐을 때 EDF는 B를 먼저 고른다. 기한을 모두 만족할 수 있는지는 각 작업의 실행 시간과 도착 시각, 가용한 CPU 시간에도 달려 있다.

### HRN(Highest Response Ration Next)스케줄링 알고리즘
- 대기 시간과 실행 시간을 함께 고려해 프로세스의 우선순위를 정하는 방식 
- 대기 중인 프로세스 중 응답률(response ration)이 가장 높은 프로세스를 우선 실행합니다. 
	- 응답률 계산 
		- (대기 시간 + 실행 시간) / 실행 시간 
		- 대기 시간 
			- 프로세스가 준비 큐에 도착한 후 현재까지 기다린 시간
		- 실행 시간
			- 프로세스를 CPU에서 실제로 실행하는 데 필요한 시간 
	- 응답률이 높을수록 우선순위가 높다. 
	- **작동 과정**
		1. 프로세스의 응답률을 계산한 후, 응답률이 가장 높은 프로세스를 실행
		2. 선택한 프로세스가 CPU를 할당받아 실행합니다. 실행 완료하면 해당 프로세스는 종료합니다. 
- 대기 시간이 긴 프로세스의 응답률을 높게 평가하기 때문에 오랜 기간 대기한 프로세스를 우선 처리할 수 있다.
	- 그래서 기아 문제를 방지하고, 평균 대기 시간을 줄이는 효과를 얻을 수 있다. 
- **단점**
	- 실행 시간이 긴 프로세스가 실행 중일 경우 급하게 처리해야 하는 프로세스가 CPU를 할당받기 어렵습니다.
	- 각 프로세스의 응답률을 계산해야 하므로 추가 연산이 필요 
---
### note 
- batch job(배치 작업)
	- 사용자가 개입 없이 정해진 작업을 묶어서 일괄로 처리하는 작업을 의미합니다. 
	- 실시간 상호 작용이 필요 없고, 대량의 데이터를 처리하거나 시간이 오래 걸리는 작업을 주로 수행 
## 혼합형 스케줄링
- 실시간 작업, 배치 작업, 상호작용 작업 등 여러 작업이 혼재하는 시스템에서는 단일 스케줄링 알고리즘만으로는 모든 요구사항 만족이 어렵습니다. 

### 다단계 큐 스케줄링 알고리즘(multilevel queue)
- 작업을 여러 그룹으로 분류해 각각 큐를 생생하고, 각 큐에 서로 다른 스케줄링 알고리즘을 적용하는 방식입니다. 
- **큐 분류**
	- 시스템 작업 큐 
		- 시스템에서 중요한, 우선순위가 높은 프로세스를 위한 큐 
	- 상호작용 작업 큐 
		- 사용자와의 상호작용이 필요한 대화형 프로세스를 위한 큐 
	- 배치 작업 큐 
		- 실시간 응답이 필요 없고 긴 실행 시간을 요구하는 프로세스를 위한 큐 
	- 백그라운드 작업 큐
		- 시스템 모니터링과 같은 백그라운드 작업을 위한 큐 
- **작동 방식**
	1. 프로세스가 도착하면 사전에 정해진 기준에 따라 적절한 큐에 배치 
	2. 각 큐는 개별적으로 CPU 스케줄링을 수행 
	3. 높은 우선순위 큐가 비었을 때만 낮은 우선순위 큐가 CPU를 사용할 수 있다. 
	4. 주로 높은 우선순위 큐에서는 라운드 로빈을, 낮은 우선순위 큐에서는 FCFS를 사용 
- 서로 다른 작업 유형을 별도의 큐로 관리해 각 유형에 맞는 스케줄리을 적용할 수 있다. 
- **단점**
	- 프로세스가 특정 큐에 배치되면 해당 큐에 고정되어 필요에 따라 큐를 이동하거나 우선순위를 조정하기 어렵습니다. 
	- 우선순위가 낮은 큐에 배정된 프로세스는 우선순위가 높은 큐가 프로세스를 모두 실행할 때까지 계속 대기하게 되어 기아 현상이 발생할 수 있습니다. 
### 다단계 피드백 큐 스케줄링 알고리즘(multilevel feedback queue)
- 프로세스의 우선순위를 동적으로 조정해 CPU시간을 분배하는 방식입니다. 
- 큐마다 서로 다른 우선순위와 CPU 시간 할당량을 설정해 짧은 작업은 빠르게 실행하고 긴 작업은 점진적으로 낮은 우선순위 큐에서 처리합니다. 
- **작동 방식**
	1. 새로운 프로세스는 가장 높은 우선순위 큐(짧은 시간 할당량 큐)에 배치된 후 실행 
	2. 할당 시간 안에 실행을 완료하지 못하면 낮은 우선순위 큐로 이동 
	3. 입출력 요청 등 특정 조건을 만족하면 다시 우선순위가 높은 큐로 이동할 수 있습니다. 
- 높은 우선순위 큐에서 짧은 작업을 빠르게 처리해 사용자에게 짧은 응답 시간을 제공합니다. 
- 낮은 우선순위 큐에 있는 작업이 지나치게 오래 대기하지 않도록 우선순위를 점진적으로 높여 기아 상태를 방지 
- **단점**
	- 여러 큐를 사용하고 각 큐에 서로 다른 스케줄링 알고리즘을 작용해야 하므로 설계와 구현이 복잡 
	- 프로세스가 여러 큐 사이를 이동할 때마다 추가로 연산하고 이를 관리하는 오버헤드가 발생 

## 스케줄링 단계 
- O·S는 프로세스를 효율적으로 자원을 최적화하기 위해 스케줄링을 장기, 중기, 단기 단계로 나눠 운영합니다. 
- 큐들은 운영체제에서 프로세스를 관리하기 위해 사용하는 공간입니다. 
- **큐의 역할**
	- 작업 큐(job queue)
		- 시스템에 들어오는 모든 작업이 처음으로 대기하는 큐
		- 장기 스케줄러가 이 큐에서 작업을 선택해 메모리에 로드하고 준비 큐로 이동 
	- 준비 큐(Ready queue)
		- CPU를 할당받으려는 프로세스들이 모여 있는 큐
		- 프로세스가 메모리에 로드되어 실행할 준비가 되면 이 큐에 들어가고, CPU를 할당받을 때까지 가다립니다. 
	- 입출력 큐(I/O queue)
		- 입출력 작업을 기다리는 프로세스들이 모여 있는 큐
		- CPU에서 실행 중인 프로세스가 입출력 장치를 사용해야 할 경우 해당 작업이 완료될 때까지 이 큐에서 대기해야합니다. 
### 장기 스케줄링(Long-term scheduling)
- 작업 큐에 들어온 새로운 프로세스 중에서 실행할 프로세스를 선택해 준비 큐로 보내는 과정입니다. 
- **작동 방식**
	1. 작업 큐에서 새로운 작업을 검토합니다. 
	2. 시스템 자원(CPU, 메모리 등)의 사용 상태를 고려해 실행할 작업을 결정
	3. 결정한 작업을 준비 큐로 이동시켜 CPU의 할당을 기다리게 합니다. 
- 장기 스케줄러는 비선점형 방식으로 작동해 한번 선택한 작업은 중기 또는 단기 스케줄러가 개입할 때까지 유지합니다. 
- 주기적으로 실행하며, 시스템이 동시에 처리할 수 있는 작업의 최대 수를 제한해 과도한 작업 수로 인한 병목 현상을 줄입니다. 
- CPU와 입출력 작업 비율을 조정해 시스템 성능을 최적화합니다. 
- **단점**
	- 장기 스케줄러는 프로세스를 선택하고 나면 변경이 불가능해 유연성이 낮다. 
	- 동적 환경에서는 시스템의 효율성과 응답성을 저하시킬 수 있습니다. 
### 중기 스케줄링(medium-term scheduling)
- 메모리 자원을 효율적으로 관리하기 위해 프로세스를 메모리에서 보조 기억 장치(디스크)로 이동하거나 다시 메모리로 불러오는 과정 
	- 즉, 실행 중인 프로세스를 일시적으로 중단했다가 재개할 수 있도록 조정합니다. 
- **작동 방식**
	1. 프로세스가 실행 중에 입출력 작업을 요청하거나 메모리가 부족해지면 중기 스케줄러가 개입 
	2. 실행 중인 프로세스를 디스크로 이동해 메모리를 확보 
	3. 프로세스가 필요할 때 다시 메모리로 가져와 실행을 재개합니다. 
- 중기 스케줄링은 선점형 방식으로 작동하며, 시스템 자원 현황에 따라 프로세스 개수를 동적으로 관리 
- 또한, 스와핑 기법을 사용해 메모리 공간을 확보 
	- 스와핑(Swapping)기법 
		- 현재 메모리에 있는 프로세스를 디스크로 내보내고, 필요한 경우 다시 메모리로 불러오는 방식 
		- **스왑 아웃(swap out)**
			- 비활성 상태이거나 대기 상태로 오래 머문 프로세스를 디스크로 이동시켜 메모리 자원을 확보 
		- **스왑 인(swap in)**
			- 디스크에 있던 프로세스를 다시 메모리로 가져와 실행 준비 상태로 만드는 작업입니다. 
			- 스왑 인은 시스템 상태나 메모리 가용성에 따라 이루어집니다. 
- 중기 스케줄링은 메모리 자원을 최적화하고, 시스템 안정성을 향상하지만, 스와핑이 과도하게 발생하면 성능이 저하될 수 있습니다. 
	- 이는 디스크 접근 속도가 메모리 접근 속도보다 느리기 때문에 발생하는 문제입니다. 
### 단기 스케줄링(short-term scheduling)
- 준비 큐에서 실행할 프로세스를 선택해 CPU를 할당하는 과정 
- 장기나 중기 스케줄링보다 휠씬 빈번하게 실행되며 CPU최적화가 주요 목표입니다. 
- **작동 방식**
	1. 준비 큐에서 실행 가능한 프로세스를 선택 
	2. 선택한 프로세스에 CPU를 할당해 실행
	3. 프로세스가 종료하거나 입출력 요청 등으로 중단되면 새로운 프로세스를 선택해 CPU를 할당합니다.
- **단기 스케줄링 발생 조건**
	- 프로세스 생성 시 
		- 새로운 프로세스가 준비 큐에 추가되면 CPU를 할당할 프로세스를 설정합니다. 
	- 프로세스 종료 시 
		- 한재 실행 중인 프로세스가 종료되면 준비 큐에서 새로운 프로세스를 선택합니다. 
	- 입출력 발생 시 
		- 실행 중인 프로세스가 입출력 작업을 요청하면 CPU를 반납하고 다른 프로세스를 실행 
	- 입출력 완료 시 
		- 입출력 대기 중이던 프로세스가 준비 큐로 복귀하면 실행 여부를 결정합니다. 
	- 입터럽트 발생 시 
		- 하드웨어 또는 소프트웨어 인터럽트가 발생하면 현재 실행 중인 프로세스를 일시 중단하고 새로운 프로세스를 실행합니다. 
- 단기 스케줄링에서는 CPU를 할당하기 위해 FCFS, SJF, RR, 우선순위 등 다양한 스케줄링 알고리즘을 사용합니다. 
- 단기 스케줄링 덕분에 즉시 프로세스를 실행할 수 있고 시스템 성능을 최적화할 수 있지만, 특정 프로세스가 지속적으로 CPU를 할당받지 못하는 기아 현상이 발생 가능합니다.
