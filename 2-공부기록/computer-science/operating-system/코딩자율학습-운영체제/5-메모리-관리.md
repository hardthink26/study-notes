- 물리 메모리와 논리 메모리는 컴퓨터의 메모리 관리에서 사용하는 개념 
- 물리 메모리는 실제 하드웨어인 RAM과 같은 실질적인 메모리 자원을 의마하며, 하드웨어 관점에서 메모리를 나타냅니다. 
- 논리 메모리는 프로세스가 사용하는 추상화된 메모리 공간으로, 소프트웨어 관점에서 메모리를 정의 

## 물리 메모리Physical memory)
- 컴퓨터에 실제로 장착한 하드웨어 메모리입니다. 
- 물리 메모리는 실행 중인 프로그램과 프로그램에서 필요한 데이터를 저장하며, CPU가 직접 접근해 데이터를 직접 읽고 쓸 수 있습니다. 
- **물리 주소(physical address)**
	- 물리 메모리에서 특정 데이터가 저장된 정확한 위치를 나타내는 주소 
- 물리 메모리의 크기가 한정되기 때문에 운영체제는 가상 메모리 기법을 활용해 부족한 물리 메모리를 보완 
	- **가상 메모리(virtual memory)**
		- 디스크의 일부를 메모리처럼 활용해 논리적으로 더 큰 메모리 공간을 제공하는 기술 
## 논리 메모리(Logical memory)
- 프로그램을 실행할 때 CPU가 생성하는 주소 공간입니다. 논리 주소(logical address) 또는 가상 주소(virtual address)라고 합니다. 
- 논리 메모리는 물리 메모리와 직접 연결되지 않으며, 운영체제의 메모리 관리 장치(MMU, Memory Management Unit)에 의해 물리 주소로 변환합니다. 
- **논리 주소-> 물리 주소 변환 과정**
	1. CPU가 논리 주소를 생성 
	2. MMU는 운영체제가 관리하는 메모리 매핑 정보를 이용해 물리 주소를 계산 
	3. 반환한 물리 주소를 사용해 CPU는 실제 메모리에 데이터를 읽거나 씁니다. 
- **물리 주소 계산**
	- 물리 주소 = 시작 주소 + 오프셋 
		- 시작 주소(base address)
			- 프로세스가 할당받은 메모리의 시작 위치를 의미 
		- 오프셋(offset)
			- 프로세스 내에서 특정 데이터가 위치하는 상대적 거리를 나타냅니다. 
	- 오프셋 값이 프로세스가 할당받은 메모리 크기를 초과하면 세그먼테이션 폴트(메모리 접근 오류)가 발생해 강제 종료될 수 있습니다. 
		- 운영체제는 이러한 오류를 방지하기 위해 프로세스마다 독립적인 주소 공간을 할당합니다. 또한, 프로세스 간 메모리 충돌을 차단해 각 프로세스가 자신의 메모리 영역만 안전하게 접근하도록 보호합니다. 
## 시점에 따른 메모리 할당 방식 
- 프로그램을 원할하게 실행하려면 메모리 할당이 제대로 이루어져야 합니다. 
- **메모리 할당(memory allocation)**
	- 프로그램을 실행할 때 필요한 메모리 공간을 제공하고 관리하는 과정입니다. 
- 메모리 할당 과정 
	1. 프로그램을 실행하면 필요한 메모리 공간을 운영체제에 요청합니다. 
	2. 운영체제는 사용 가능한 메모리를 탐색해 적절한 크기를 할당합니다. 
	3. 운영체제는 프로그램에 논리 주소를 제공하고, 필요에 따라 물리 주소와 매핑합니다. 
	4. 프로그램은 할당된 메모리 공간을 사용해 작업을 수행하거나 데이터를 사용합니다. 
	5. 프로그램이 메모리 공간을 더 이상 사용하지 않으면 해당 메모리를 해제해 다른 프로세스가 사용할 수 있도록 반환합니다. 

### 정적 할당(static allocation)
- 프로그램을 실행하기 전(컴파일 시점)에 메모리를 고정 크기로 할당하는 방식입니다. 
	- **컴파일 시점(cimpile time)**
		- 소스 코드가 컴파일러에 의해 기계어로 변환되는 시점
- 정적 할당에서는 컴파일러가 변수와 함수의 타입을 확인하고 메모리 할당을 결정합니다. 
- 따라서 프로그램 실행 중에 메모리 크기가 변경되지 않습니다. 
- 프로그램을 종료하면 할당된 메모리가 자동으로 해제되므로 메모리 누수의 위험이 줄어듭니다. 또한, 메모리 주소가 고정되어 있어 디버깅할 때 위치를 쉽게 추적할 수 있습니다. 
- **단점**
	- 프로그램 실행 중에 변수나 자료구조의 크기를 변경할 수 없어 동적 상황에 대처하기 어렵습니다. 
		- 만약 필요한 것보다 많은 메모리를 할당할 경우 사용하지 않는 공간이 발생 가능 
### 동적 할당(dynamic allocation)
- 프로그램 실행 중(런타임)에 메모리 크기와 위치를 결정하는 방식입니다. 
	- 이 방식은 메모리를 유연하게 사용할 수 있으며, 가변 크기의 데이터를 처리하는 데 유용합니다. 
- **단점**
	- 동적 할당은 메모리 할당과 해제 과정에서 추가 연산이 필요하므로 성능에 영향 줄 수 있음
	- 또한, 동적으로 할당한 메모리를 해제하지 않으면 메모리 누수가 발생해 시스템 메모리가 부족해질 수 있다. 

## 공간 배치에 따른 메모리 할당 방식 
- 메모리 할당 방식은 프로세스의 메모리를 물리적으로 연속한 공간에 배치하는지 여부에 따라 연속할당과 비연속 할당으로 나뉩니다. 
### 연속 할당(contiguous allocation)
- 프로세스의 전제 메모리 공간을 물리적 메모리의 연속한 주소 공간에 배치하는 방식입니다. 
- 이 방식은 메모리 공간의 시작 주소와 크기가 고정되어 메모리를 관리하기가 상대적으로 쉽습니다.
- 또한, 메모리를 연속해서 배치하기 때문에 데이터 접근 속도가 빠르고 주소 반환이 간단합니다. 
- 연속 할당 방식에는 고정 분할과 가변 분할이 있습니다. 
- **고정 분할(fixed partitioning)**
	- 메모리를 일정한 크기의 여러 파티션으로 나누고, 각 파티션을 하나의 프로세스에 할당하는 방식입니다. 
		- 파티션 크기는 같은 크기(균등 분할)또는 다른 크기(비균등 분할)로 설정 가능 
	- **작동 방식**
		1. 운영체제가 메모리룰 일정 크기의 파티션으로 나눕니다. 
		2. 프로세스를 실행하면 해당 프로세스의 크기와 가장 맞은 파티션에 로드합니다. 만약 프로세스의 크기가 파티션보다 작다면 파티션 내에 남는 공간이 생깁니다. 
		3. 프로세스를 종료하면 해당 파티션은 비게 되어 다른 프로세스가 사용할 수 있습니다. 
	- **property**
		- 고정 분할 방식은 고정 크기의 파티션을 사용해 각 프로세스를 특정 파티션에 할당하는 구조이므로 프로세스가 메모리의 어느 위치에 있는지 쉽게 계산이 가능합니다. 
			- 그래서 주소 변환이 간단하고 빠릅니다. 
		- 고정된 파티션 구조는 메모리 관리가 쉽습니다. 
			- 각 파티션에 프로세스를 할당하고 종료하면 해당 파티션을 비워 두는 방식으로 관리할 수 있습니다. 
		- 하지만, 내부 단편화(internal fragmentation)이 발생할 수 있습니다. 
			- 내부 단편화 
				- 할당된 메모리 공간 내에 사용하지 않는 공간이 발생하는 현상입니다. 
				- 이렇게 남은 공간은 다른 프로세스가 사용할 수 없기 때문에 메모리를 비효율적으로 사용합니다. 
		- 또한, 고정 분할 방식에서는 각 파티션의 크기가 고정되므로 특정 프로세스가 요구하는 메모리 크기와 파티션 크기가 일치하지 않으면 해당 프로세스를 메모리에 적재할 수 없습니다. 
			- 이러한 상태를 적재 불가(load failure)라고 합니다. 
- **가변 분할(variable partitioning)**
	- 프로세스의 크기에 따라 메모리를 동적으로 할당하는 방법입니다. 
	- **작동 방식**
		1. 프로세스가 실행될 때 필요한 메모리 크기를 요청합니다. 
		2. 운영체제는 메모리에서 프로세스가 요청한 크기에 적합한 빈 공간을 찾아 프로세스에 할당 
		3. 프로세스를 종료하면 할당된 메모리를 반환해 다른 프로세스에서 사용할 수 있도록 합니다. 
	- **property**
		- 가변 할당은 필요한 만큼만 메모리를 할당하므로 메모리 낭비를 줄이고, 다양한 크기의 프로세스를 효과적으로 처리할 수 있습니다. 
		- 그러나 메모리 할당과 해제가 반복되면서 여러 작은 빈 공간이 생기는 단편화 문제 발생 가능하며 외부 단편화라고 합니다. 
			- 외부 단편화(external fragmentation)
				- 전체적으로 남은 메모리 공간은 충분하지만, 연속한 메모리 공간이 부족해 새로운 프로세스의 메모리 요청을 수용하지 못하는 상태를 의미합니다. 
				- 외부 단편화 해결 방안으로는 메모리 통합과 효율적인 할당 알고리즘 사용이 있습니다. 
### 외부 단편화 해결 방안 
- **메모리 통합(memory compaction)**
	- 사용 중인 메모리를 한쪽으로 이동시켜 연속한 빈 공간을 만드는 방법 
	- 프로세스의 메모리 위치를 재배치해야 해서 처리 시간이 추가로 필요하지만, 외부 단편화를 효과적으로 처리 가능 
- **할당 알고리즘**
	- 프로세스가 메모리를 요청할 때 어떤 공간에 할당할 지 결정하는 규칙이나 전략을 의미합니다. 
	- **최초 적합(first fit)**
		- 프로세스가 요청한 메모리 크기에 적합한 첫 번째 빈 공간을 찾아 할당하는 알고리즘입니다. 
		- **작동 방식**
			1. 메모리의 빈 공간을 찾아 처음부터 끝까지 순차적으로 탐색합니다. 
			2. 요청한 메모리 크기보다 크거나 같은 첫 번째 빈 공간을 선택합니다. 
			3. 선택한 빈 공간을 프로세스에 할당합니다. 
		- **특징**
			- 순차적으로 탐색하며 첫 번째 적합한 공간을 선택하기 때문에 구현이 쉽습니다. 
			- 빈 공간을 깊게 분석하지 않으므로 탐색 시간도 비교적 짧습니다. 
			- 하지만 할당한 후 빈 공간이 작게 남아 외부 단편화 현상을 초래할 수 있습니다. 
			- 최초 적합은 빠른 메모리 할당이 필요한 경우 유용하지만, 외부 단편화 문제를 해결하려면 다른 할당 알고리즘을 병행하거나 주기적으로 메모리 통합을 수행해 조각화를 관리해야합니다. 
	- **최적 적합(best fit)**
		- 메모리에서 사용 가능한 모든 빈 공간을 탐색해 요청한 메모리 크기에 가장 적합한 공간을 찾는 알고리즘입니다. 
		- **작동 방식**
			1. 메모리에서 사용 가능한 빈 공간을 모두 탐색합니다. 
			2. 프로세스가 요청한 메모리 크기보다 크거나 같은 빈 공간 중 가장 작은 공간을 선택합니다. 
			3. 선택한 빈 공간을 프로세스에 할당합니다. 
		- **특징**
			- 남은 공간을 최소화해 상대적으로 메모리를 효율적으로 사용 가능합니다. 
			- 요청한 크기와 가장 가까운 크기의 공간을 선택하기 때문에 큰 메모리 공간이 잘게 나타나는 것을 방지 
			- 하지만 요청한 메모리 크기에 딱 맞는 공간을 선택하다 보면 상대적으로 작은 빈 공간이 많이 남게 됩니다. 이럴 경우 여전히 외부 단편화 문제 발생 가능합니다. 
			- 최적 적합은 사용 가능한 모든 빈 공간을 탐색해야 하므로 시간이 많이 걸립니다. 
		- 최적 적합 알고리즘의 효율성을 높이려면 주기적으로 메모리 통합을 수행해 단편화를 줄이고, 사용 가능한 빈 공간을 더 효율적으로 관리해야 합니다. 
	- **최악 적합(worst fit)**
		- 요청한 메모리 크기를 만족하는 가장 큰 빈 공간을 찾아 할당하는 알고리즘 
		- **작동 방식**
			1. 메모리에서 사용 가능한 빈 공간을 모두 탐색합니다. 
			2. 프로세스가 요청한 메모리의 크기보다 큰 빈 공간 중 가장 큰 공간을 선택합니다. 
			3. 선택한 빈 공간에 프로세스를 할당하고 남은 작은 공간은 새로운 빈 공간으로 유지합니다. 
		- **특징**
			- 큰 빈 공간을 나누어 사용하기 때문에 할당 후에도 비교적 큰 공간이 남을 수 있습니다. 
			- 최악 적합은 크기를 기준으로 최댓값을 찾으면 돼서 구현이 상대적으로 간단합니다. 
			- 그러나 모든 빈 공간을 탐색하며 큰 공간을 찾아야 하므로 탐색 시간이 오래 걸릴 수 있습니다. 
			- 큰 크기 요청에 큰 요청을 할당하면 작은 크기의 빈 공간이 남아 이후 요청을 처리하지 못하는 외부 단편화 발생할 수 있습니다. 
### 비연속 할당(non-contiguous allocation)
- 프로세스가 요청한 메모리를 연속하지 않은 여러 공간에 나누어 할당하는 방식입니다. 
- 프로세스는 할당받은 메모리를 연속적인 주소 공간으로 인식하지만, 실제로는 물리 메모리의 여러 곳에 분산되어 있습니다. 
- O·S는 프로세스가 메모리를 사용할 때 메모리 관리 장치(MMU)를 사용해 논리 주소를 올바른 물리적 위치로 매핑합니다. 
- 비연속 할당 방식에는 페이징과 세그먼테이션이 있습니다. 
- **페이징(paging)**
	- 운영체제가 프로세스를 일정 크기의 블록(페이지)으로 나누어 물리 메모리에 할당하는 방법입니다. 
	- 이 방법은 논리 메모리와 물리 메모리를 페이지와 프레임으로 분리해 관리합니다. 
	- **작동 방식**
		1. 프로세스를 생성하면 해당 프로세스의 주소 공간(논리 메모리)을 페이지 단위로 나눕니다. 
		2. 물리 메모리도 페이지와 같은 크기의 프레임 단위로 나눕니다. 
		3. 운영체제가 페이지 테이블을 생성하고 초기화해 논리 주소와 물리 주소 간 매핑을 관리합니다. 
		4. 프로세스를 실행할 때 필요한 메모리 공간을 요청하면 운영체제는 사용 가능한 프레임을 탐색해 할당합니다. 
		5. 할당한 프레임을 페이지 테이블에 저장해 논리 주소(페이지 번호)와 물리 주소(프레임 번호)를 매핑합니다. 
		6. 프로세스가 요청한 페이지가 메모리에 없으면 페이지 폴트가 발생합니다. 그러면 운영체제는 해당 페이지를 디스크에서 메모리로 가져오고 해당 내용으로 페이지 테이블을 갱신합니다. 
		7. 프로세스를 종료하면 해당 프로세스의 페이지 테이블이 삭제되고, 사용한 프레임을 다른 프로세스에 할당할 수 있도록 반환합니다. 
	- 페이지 테이블(page table)
		- 운영체제가 관리하는 데이터 구조로, 각 프로세스의 논리 주소와 물리 주소 간 매핑 정보를 저장합니다. 
		- 운영체제는 프로세스가 생성될 때 페이지 테이블을 생성해 초기화하고, 메모리 할당이 이루어질 때마다 페이지 테이블을 갱신합니다. 
		- **포함 정보**
			- 프레임 번호 
				- 해당 페이지가 물리 메모리의 어느 프레임에 저장되었는지 나타냅니다. 
			- 유효 비트 
				- 페이지가 현재 메모리에 존재하는지 여부를 나타냅니다. 
				- 유효비트가 1이면 페이지가 메모리에 존재합니다. 
				- 유효비트가 0이면 페이지가 디스크와 같은 보조 기억 장치에 저장된 것이며, 페이지 폴트가 발생한 것입니다. 
			- 접근 권환 
				- 페이지에 대한 읽기, 쓰기, 실행 권한을 나타냅니다. 
			- **페이지 테이블을 이용한 주소 변환 과정**
				1. CPU가 논리 주소를 생성합니다. 논리 주소는 페이지 번호와 오프셋으로 구성됩니다. 
					- 페이지 번호: 특정 페이지를 식별하는데 사용 
					- 오프셋: 특정 페이지 내에서 데이터의 위치를 가리킵니다. 
				2. 운영체제는 페이지 테이블에서 해당 페이지가 물리 메모리의 어느 프레임에 해당하는지 확인합니다. 
				3. MMU에서 프레임 번호와 오프셋을 조합해 물리 주소로 변환합니다. 
					- 물리 주소 = (프레임 번호 * 페이지 크기) + 오프셋 
				4. 변환한 물리 주소를 사용해 실제 메모리에 접근해 데이터를 읽거나 씁니다. 
	- 페이징 기법은 연속한 물리 메모리가 필요하지 않아 작은 공간도 활용할 수 있고, 가변 분할 방식과 달리 메모리 공간이 조각조각 나뉘어도 페이지 단위로 할당할 수 있어 메모리를 효율적으로 사용 가능합니다. 
	- **단점**
		- 페이지 크기가 너무 크면 각 페이지 내에서 사용하지 않는 공간이 생길 수 있습니다. 
		- 프로세스마다 페이지 테이블을 위한 메모리가 추가로 필요합니다.
		- 프로세스가 메모리에 접근할 때마다 페이지 테이블을 참조해야 하므로 속도가 느려질 수 있다. 
			- 이 문제는 TLB(Translation Loadaside Buffer)로 캐싱해 속도를 높일 수 있다. 
- **세그먼테이션(segmentation)**
	- 메모리를 고정 크기의 페이지로 나누는 페이징과 달리, 세그먼테이션은 논리적인 단위인 세그먼트(segment)로 메모리를 나눠 관리하는 방식입니다. 
		- 프로그램에서 사용하는 코드, 데이터, 힙, 스택 등의 영역을 각각 독립적인 세그먼트로 구분해 메모리를 할당합니다. 
	- 각 프로세스마다 별도의 segment table을 가지고 있으며, 이 테이블을 통해 해당 프로세스의 메모리 접근을 관리합니다. 
		- 세그먼트 테이블에 저장되는 정보 
			- 세그먼트 시작 주소(base address)
				- 물리 메모리에서 각 세그먼트의 시작 위치를 나타냅니다. 
			- 세그먼트 크기(limit)
				- 세그먼트의 최대 크기(최대 오프셋 값)을 의미합니다. 
			- 인덱스
				- 세그먼트 번호를 의미합니다. 
	- **세그먼테이션에서 논리 주소 -> 물리 주소 변환 과정**
		1. 프로세스가 논리 주소를 생성합니다. 
			- 논리 주소는 (세그먼트 번호, 오프셋)으로 구성됩니다. 
		2. 운영체제가 세그먼트 번호(인덱스)를 이용해 세그먼트 테이블에서 해당 세그먼트의 정보를 찾습니다. 
		3. 물리 주소를 계산해 변환합니다. 
			- 이때 논리 주소의 오프셋이 세그먼트 크기보다 작은지 확인합니다. 
				- 오프셋이 세그먼트 주소보다 작으면 유효한 주소, 즉 접근 가능한 주소입니다. 
				- 만약 크면 세그먼트 범위를 초과하는 메모리 접근이므로 세그먼테이션 폴트가 발생합니다. 
		4. 변환한 물리 주소로 물리 메모리에 접근해 데이터를 읽거나 씁니다. 
	- 세그먼테이션은 코드, 데이터, 힙, 스택을 나누어 관리하므로 프로그램의 구조를 잘 반영할 수 있다. 
	- 각 영역에 필요한 만큼만 메모리를 할당하기 때문에 페이징처럼 정해진 크기보다 작은 메모리를 낭비하는 문제가 없다. 
	- **단점**
		- 세그먼트 크기가 가변적이므로 연속한 빈 공간을 찾기가 어려워 외부 단편화가 발생 가능 
		- 세그먼트 테이블을 참조하는 주소 변환 과정이 추가로 필요하므로 오버헤드가 발생합니다. 
### 세그먼테이션 + 페이징 
- 각 기법의 단점을 보완하는 방법 
- 즉, 세그먼트를 다시 작은 페이지로 나눠 관라하는 방법입니다. 
	- 세그먼트를 고정 크기의 페이지로 나누어 할당하면 연속적인 공간이 필요하지 않아 외부 단편화가 사라집니다. 
- **단점**
	- 세그먼트 테이블을 찾고, 해당 세그먼트 페이지 테이블을 추가로 찾아야합니다. 
		- 즉, 주소 변환을 두 번 해야해서 오버헤드가 증가 

## 가상 메모리 
- 컴퓨터의 물리 메모리(RAM)은 크기가 한정적입니다. 
- 이를 해결하기 위해 운영체제는 가상 메모리 기술을 사용합니다. 
### 가상 메모리(virtual memory)
- 보조 기억 장치(디스크)의 일부를 확장된 메모리처럼 사용하는 기술 
- 이 기술은 프로그램이 물리 메모리 크기와 관계없이 더 큰 메모리 공간을 사용할 수 있게 합니다. 
- **작동 원리**
	- 프로세스마다 독립적인 논리 주소 공간을 제공해 각 프로세스가 전체 메모리를 독점하는 것처럼 작동 
	- 실제로는 필요한 데이터만 물리 메모리에 로드해 메모리 사용을 최적화하고 시스템의 효율성을 높임 
- **작동 과정(논리 주소와 물리 주소 사이에서 변환 작업 수행)**
	1. 프로세스가 메모리에 접근할 때(변수 읽기, 코드 실행 등) 논리 주소를 사용 
	2. 운영체제는 페이지 테이블을 사용해 논리 주소를 물리 주소 또는 디스크 위치와 매핑합니다. 
	3. MMU는 페이지 테이블을 참조해 논리 주소를 물리 주소로 변환 
	4. 변환된 물리 주소로 데이터 읽기 또는 쓰기를 수행합니다. 
		- 데이터가 물리 메모리에 있다면 바로 접근 
		- 데이터가 물리 메모리에 없으면 페이지 폴트가 발생합니다. 
			- 이 경우 운영체제가 디스크에서 해당 데이터를 물리 메모리에 로드한 후 사용 
- 가상 메모리는 각 프로세스에 독립적인 메모리 공간을 제공하므로 여러 프로세스를 동시에 실행 가능
- 한 프로세스가 다른 프로세스의 메모리에 접근할 수 없어 보안이 강화됩니다. 
- 가상 메모리는 필요한 데이터만 물리 메모리에 로드해 메모리 사용을 최적화
- **단점**
	- 가상 메모리는 논리 주소를 물리 주소로 변환하는 과정에서 추가 시간을 소요하므로 오버헤드가 발생합니다. 
	- 필요한 데이터가 물리 메모리에 없으면 페이지 폴트가 발생합니다. 
	- 디스크 입출력 속도가 물리 메모리보다 느리기 때문에 디스크 접근이 많아지면 전체 시스템 성능이 저하될 수도...
### 스와핑 
- 가상 메모리 시스템에서 운영체제는 사용하지 않는 프로세스의 메모리 일부를 디스크로 이동해 물리 메모리의 공간을 확보를 의미 
- 이때 임시로 사용하는 디스크 공간을 **스왑 공간(swap space)** 라고 합니다. 
- **사용처**
	- 여러 프로세스를 동시에 실행할 때, 물리 메모리가 부족해지면 활용 
- **스와핑 작동 순서**
	1. 여러 프로그램이 동시 실행하면 물리 메모리 공간이 부족해질 수 있다. 이때 운영체제는 사용하지 않는 프로세스의 메모리 페이지를 스왑 공간으로 이동해 물리 메모리를 확보합니다. 
		 - 이를 스왑 아웃(swap out)이라고 합니다. 
	2. 스왑 공간으로 이동한 프로세스를 다시 실행해야 하면 운영체제는 해당 페이지를 다시 물리 메모리로 로드합니다. 
		- 이를 스왑 인(swap in)이라고 합니다. 
- **작동 유형**
	- 페이지 스와핑(paging-based swapping)
		- 프로세스를 페이지 단위로 쪼개어 스왑 공간으로 이동하는 방식입니다. 
		- 페이지 폴트가 발생하면 필요한 페이지만 다시 물리 메모리로 불러옵니다. 
		- **장점**
			- 전체 프로세스를 이동하지 않고, 일부만 스왑해 속도를 향상하고, 물리 메모리가 부족할 때 효율적으로 사용할 수 있습니다. 
		- **단점**
			- 디스크 접근이 많아지면 성능이 저하
			- 페이지 테이블을 관리해야 해서 오버헤드가 증가 
	- 전체 프로세스 스와핑(process swapping)
		- 프로세스 전체를 디스크의 스왑 공간으로 이동하는 방식 
		- CPU가 프로세스를 실행하기 전에 물리 메모리를 다시 불러옵니다. 
		- 예전 MS-DOS, 초기 유닉스 시스템에서 사용하는 방식으로 현대 운영체제에서는 거의 사용x 
### 요구 페이징(demand paging)
- 가상 메모리 시스템에서 메모리를 효율적으로 관라하기 위해 사용하는 기법 
- 프로그램을 실행할 때 처음부터 모든 페이지를 로드하지 않고 필요한 페이지만 메모리에 적재합니다. 
- **작동 과정**
	1. 프로그램이 실행될 때 페이지 테이블만 생성하고, 실제 페이지는 로드하지 않습니다. 
	2. CPU가 필요한 페이지에 접근하려고 하면 페이지 폴트가 발생 
	3. 운영체제가 해당 페이지를 디스크에서 물리 메모리로 불러옵니다. 
	4. 페이지가 로드된 후에 CPU가 프로세스를 정상적으로 실행합니다. 
- **운영체제의 페이지 폴트 처리 과정**
	1. 프로세스가 필요한 페이지를 참조하려고 시도 
	2. 페이지 테이블에서 해당 페이지의 유효비트를 확인합니다. 
		- 0(invalid)이면 페이지가 물리 메모리에 없다는 것이므로 페이지 폴트가 발생
		- 1(valid)이면 페이지가 물리 메모리에 있으므로 정상적으로 실행 
	3. 페이지 폴트가 발생하면 CPU는 제어권을 운영체제에 넘깁니다.
	4. 운영체제가 물리 메모리에 빈 프레임이 있는지 확인합니다.
		- 빈 프레임이 있다면 해당 프레임에 페이지를 로드할 준비를 합니다.
		- 빈 프레임이 없다면 기존 페이지를 디스크로 내보내(페이지 교체) 새로운 페이지를 저장할 공간을 확보합니다. 
	5. 운영체제가 디스크에서 페이지를 읽어와 물리 메모리의 빈 프레임에 로드합니다. 
	6. 운영체제가 페이지 테이블을 업데이트합니다. 
		- 유효 비트를 0에서 1로 변경 
		- 해당 페이지에 물리 메모리의 프레임 번호를 저장합니다. 
	7. 운영체제가 중단된 프로세스를 다시 실행하고 CPU에 제어권을 반환합니다. 
- **장점**
	- 요구 페이징은 실행 시점에 필요한 페이지만 로드하므로 초기 메모리 사용량을 줄이고 불필요한 데이터가 물리 메모리에 로드되는 것을 방지할 수 있다. 
- **단점**
	- 페이지 폴트가 발생하면 디스크에서 데이터를 읽어와야 해서 성능 저하될 수 있다. 
		- 페이지 폴트가 너무 자주 발생하면 스레싱(thrashing)이 발생할 가능성이 있다. 
### 페이지 교체(page replacement)
- 요구 페이징을 사용할 때 물리 메모리가 꽉 찬 경우 어떤 페이지를 제거할지 결정하는 방법 
- **사용하는 페이지 교체 알고리즘**
	- FIFO
		- 물리 메모리에서 가장 오래된 페이지를 교체합니다. 
		- 페이지를 큐로 관리해 먼저 들어온 페이지가 먼저 나갑니다. 
		- 하지만, 오래된 페이지라도 자주 참조할 경우 비효율적이며, 벨레이디의 이상 현상 발생 가능
			- 일반적으로 프레임 수를 늘리면 페이지 폴트가 줄어드는 것이 정상이지만, 특정 조건에서는 페이지 폴트가 증가하는 현상을 펠레이디의 이상 현상이라고 함 
	- LRU
		- 가장 오랫동안 사용하지 않은 페이지를 교체합니다. 
		- 페이지 접근 시간을 따로 저장하고 추적해야 해서 구현이 복잡합니다. 
	- OPT(Optimal Page Replacement algorithm)
		- 앞으로 가장 오랫동안 사용하지 않을 페이지를 교체하는 방법 
		- 페이지 교체 성능이 가장 뛰어나며, 이론적으로 가장 적은 페이지 폴트를 보장합니다. 
		- 그러나 미래의 메모리 접근을 예측해야 해서 구현이 어렵!! 
	- LFU(Least Frequently Used)
		- 가장 적게 사용한 페이지를 교체하는 방식입니다.
		- 페이지 사용 횟수를 기록하고, 사용 횟수가 가장 적은 페이지를 교체 
		- 단기적으로 자주 사용한 페이지를 교체할 수도 있다. 
	- Clock
		- FIFO알고리즘을 개선한 알고리즘입니다. 
			- FIFO문제(가장 오래된 페이지를 교체하는 문제)를 해결하기 위해 최근에 사용한 페이지는 교체하지 않도록 하는 방식 
			- **구현 원리**
				1. 참조 비트(reference bit)를 추가해 최근 사용 여부를 확인
				2. 원형 큐 구조를 사용해 페이지를 관리 
		- 오래된 페이지를 제거하지만, 최근에 사용한 페이지라면 한 번 더 기회를 주는 방식(Second Chance)입니다. 
		- 그러나 참조 비트를 별도로 관리해야 하므로 오버헤드가 발생하고 원형 큐에서 여러 페이지를 탐색해야 하므로 페이지 교체 속도가 느려질 수 있습니다. 
			- **원형 큐(circular queue)
				- 큐의 끝이 다시 시작 부분과 연결되는 구조입니다. 
				- 배열로 구현하고 두 개의 포인터를 사용해 큐의 앞과 뒤를 추적합니다. 
### 스래싱(Thrashing)
- 페이지 폴트가 너무 자주 발생해 CPU가 실제 작업을 수행하지 못하고, 대부분의 시간을 페이지 교체에 소비하는 현상입니다. 
- 프로세스 수가 증가함에 따라 CPU 이용률도 증가 
- [프로세스 수 따른 CPU 이용률 그래프 만들 것!! ]
- **원인**
	- 페이지 교체가 너무 빈번하게 발생해 운영체제가 디스크 입출력을 처리하는 데 대부분의 시간을 소모하기 때문입니다. 
- **해결 방법**
	-  작업 집합을 메모리에 유지해 페이지 폴트를 줄입니다. 
		- 작업 집합(Working set)
			- 프로세스가 일정 시간 자주 참조하는 페이지를 의미합니다. 
		- 작업 집합을 유지하면 불필요한 페이지 교체가 줄고 페이지 폴트가 감소 
	-  현재 프로세스가 자주 접근하는 페이지를 기반으로 페이지 교체 정책을 적용합니다. 
		- OPT, LRU등을 사용해 불필요한 페이지 교체를 줄이면 자주 사용하는 페이지를 오래 유지해 스래싱을 방지 가능 
	- 동시에 실행하는 프로세스 개수를 줄여 메모리 부담을 감소시킵니다. 
		- 시스템이 처리 가능한 만큼의 프로세스만 유지하면 스래싱 방지 가능 
	- 물리 메모리 크기가 너무 적으면 페이지 폴트가 자주 발생합니다. 물리 메모리를 추가하면 스래싱 방지가능
