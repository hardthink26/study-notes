- 물리 메모리와 논리 메모리는 컴퓨터의 메모리 관리에서 사용하는 개념 
- 물리 메모리는 실제 하드웨어인 RAM과 같은 실질적인 메모리 자원을 의마하며, 하드웨어 관점에서 메모리를 나타냅니다. 
- 논리 메모리는 프로세스가 사용하는 추상화된 메모리 공간으로, 소프트웨어 관점에서 메모리를 정의 

## 물리 메모리Physical memory)
- 컴퓨터에 실제로 장착한 하드웨어 메모리입니다. 
- 물리 메모리는 실행 중인 프로그램과 프로그램에서 필요한 데이터를 저장하며, CPU가 직접 접근해 데이터를 직접 읽고 쓸 수 있습니다. 
- **물리 주소(physical address)**
	- 물리 메모리에서 특정 데이터가 저장된 정확한 위치를 나타내는 주소 
- 물리 메모리의 크기가 한정되기 때문에 운영체제는 가상 메모리 기법을 활용해 부족한 물리 메모리를 보완 
	- **가상 메모리(virtual memory)**
		- 디스크의 일부를 메모리처럼 활용해 논리적으로 더 큰 메모리 공간을 제공하는 기술 
## 논리 메모리(Logical memory)
- 프로그램을 실행할 때 CPU가 생성하는 주소 공간입니다. 논리 주소(logical address) 또는 가상 주소(virtual address)라고 합니다. 
- 논리 메모리는 물리 메모리와 직접 연결되지 않으며, 운영체제의 메모리 관리 장치(MMU, Memory Management Unit)에 의해 물리 주소로 변환합니다. 
- **논리 주소-> 물리 주소 변환 과정**
	1. CPU가 논리 주소를 생성 
	2. MMU는 운영체제가 관리하는 메모리 매핑 정보를 이용해 물리 주소를 계산 
	3. 반환한 물리 주소를 사용해 CPU는 실제 메모리에 데이터를 읽거나 씁니다. 
- **물리 주소 계산**
	- 물리 주소 = 시작 주소 + 오프셋 
		- 시작 주소(base address)
			- 프로세스가 할당받은 메모리의 시작 위치를 의미 
		- 오프셋(offset)
			- 프로세스 내에서 특정 데이터가 위치하는 상대적 거리를 나타냅니다. 
	- 오프셋 값이 프로세스가 할당받은 메모리 크기를 초과하면 세그먼테이션 폴트(메모리 접근 오류)가 발생해 강제 종료될 수 있습니다. 
		- 운영체제는 이러한 오류를 방지하기 위해 프로세스마다 독립적인 주소 공간을 할당합니다. 또한, 프로세스 간 메모리 충돌을 차단해 각 프로세스가 자신의 메모리 영역만 안전하게 접근하도록 보호합니다. 
## 시점에 따른 메모리 할당 방식 
- 프로그램을 원할하게 실행하려면 메모리 할당이 제대로 이루어져야 합니다. 
- **메모리 할당(memory allocation)**
	- 프로그램을 실행할 때 필요한 메모리 공간을 제공하고 관리하는 과정입니다. 
- 메모리 할당 과정 
	1. 프로그램을 실행하면 필요한 메모리 공간을 운영체제에 요청합니다. 
	2. 운영체제는 사용 가능한 메모리를 탐색해 적절한 크기를 할당합니다. 
	3. 운영체제는 프로그램에 논리 주소를 제공하고, 필요에 따라 물리 주소와 매핑합니다. 
	4. 프로그램은 할당된 메모리 공간을 사용해 작업을 수행하거나 데이터를 사용합니다. 
	5. 프로그램이 메모리 공간을 더 이상 사용하지 않으면 해당 메모리를 해제해 다른 프로세스가 사용할 수 있도록 반환합니다. 

### 정적 할당(static allocation)
- 프로그램을 실행하기 전(컴파일 시점)에 메모리를 고정 크기로 할당하는 방식입니다. 
	- **컴파일 시점(cimpile time)**
		- 소스 코드가 컴파일러에 의해 기계어로 변환되는 시점
- 정적 할당에서는 컴파일러가 변수와 함수의 타입을 확인하고 메모리 할당을 결정합니다. 
- 따라서 프로그램 실행 중에 메모리 크기가 변경되지 않습니다. 
- 프로그램을 종료하면 할당된 메모리가 자동으로 해제되므로 메모리 누수의 위험이 줄어듭니다. 또한, 메모리 주소가 고정되어 있어 디버깅할 때 위치를 쉽게 추적할 수 있습니다. 
- **단점**
	- 프로그램 실행 중에 변수나 자료구조의 크기를 변경할 수 없어 동적 상황에 대처하기 어렵습니다. 
		- 만약 필요한 것보다 많은 메모리를 할당할 경우 사용하지 않는 공간이 발생 가능 
### 동적 할당(dynamic allocation)
- 프로그램 실행 중(런타임)에 메모리 크기와 위치를 결정하는 방식입니다. 
	- 이 방식은 메모리를 유연하게 사용할 수 있으며, 가변 크기의 데이터를 처리하는 데 유용합니다. 
- **단점**
	- 동적 할당은 메모리 할당과 해제 과정에서 추가 연산이 필요하므로 성능에 영향 줄 수 있음
	- 또한, 동적으로 할당한 메모리를 해제하지 않으면 메모리 누수가 발생해 시스템 메모리가 부족해질 수 있다. 

## 공간 배치에 따른 메모리 할당 방식 
- 메모리 할당 방식은 프로세스의 메모리를 물리적으로 연속한 공간에 배치하는지 여부에 따라 연속할당과 비연속 할당으로 나뉩니다. 
### 연속 할당(contiguous allocation)
- 프로세스의 전제 메모리 공간을 물리적 메모리의 연속한 주소 공간에 배치하는 방식입니다. 
- 이 방식은 메모리 공간의 시작 주소와 크기가 고정되어 메모리를 관리하기가 상대적으로 쉽습니다.
- 또한, 메모리를 연속해서 배치하기 때문에 데이터 접근 속도가 빠르고 주소 반환이 간단합니다. 
- 연속 할당 방식에는 고정 분할과 가변 분할이 있습니다. 
- **고정 분할(fixed allocation)**
	- 메모리를 일정한 크기의 여러 파티션으로 나누고, 각 파티션을 하나의 프로세스에 할당하는 방식입니다. 
		- 파티션 크기는 같은 크기(균등 분할)또는 다른 크기(비균등 분할)로 설정 가능 
	- **작동 방식**
		1. 운영체제가 메모리룰 일정 크기의 파티션으로 나눕니다. 
		2. 프로세스를 실행하면 해당 프로세스의 크기와 가장 맞은 파티션에 로드합니다. 만약 프로세스의 크기가 파티션보다 작다면 파티션 내에 남는 공간이 생깁니다. 
		3. 프로세스를 종료하면 해당 파티션은 비게 되어 다른 프로세스가 사용할 수 있습니다.
