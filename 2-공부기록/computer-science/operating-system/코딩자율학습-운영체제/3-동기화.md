- 컴퓨터는 여러 프로그램을 동시해 실행하는 것처럼 보이지만, 실제로는 multitasking, time-sharing시스템을 통해 번갈아 가며 실행 
- 운영체제는 가 프로세스에 일정한 CPU 시간을 할당해 동시에 실행되는 것처럼 보이도록 하고, 특정 프로세스가 CPU을 독점하지 못하도록 짧은 시간 동안만 CPU를 할당합니다. 이를 통해 병렬 처리(parallel processing)가 가능해짐 
	- 병렬 처리에서는 데이터의 정확성과 신뢰성을 보장하는 데이터 무결성(integrity), 데이터가 특정 규칙이나 제약 조건을 준수하는 상태를 의미하는 일관성(consistency), 시스템이 변화나 오류에 얼마나 잘 견디고 지속적으로 작동할 수 있는지를 나타내는 안정성(stability)을 보장하는 것이 중요 
	- 이를 위해 동기화가 필요 !!! 

### 동기화(Synchronization)
- 여러 프로세스나 스레드가 공유 자원에 접근할 때 이들의 실행 순서를 조정해 데이터의 무결성과 일관성을 보장하는 기법 
- 주로 멀티스레드나 멀티프로세스 환경에서 발생하는 문제를 해결하는 데 필요 
- **동기화와 관련된 문제**
	- **경쟁 조건(race condition)**
		- 두 개 이상의 프로세스나 스레드가 동시에 공유 자원에 접근해 프로그램의 결과가 예측할 수 없게 되는 상황 
		- 경쟁 조건은 특정 자원에 대한 접근 순서에 따라 결과가 달라질 수 있고 이는 프로그램의 논리적 오류를 초래할 수 있습니다. 
		- 동기화는 이런 경재 조건을 방지해 프로그램의 동작을 예측할 수 있습니다. 
	- **데이터 경합(data race)**
		- 경쟁 조건의 한 형태로 두 개 이상의 프로세스나 스레드가 공유 자원을 동시에 읽고 수정하는 상황 
		- 실행 순서가 보장되지 않으므로 데이터의 무결성이 손상될 수 있습니다. 
	- **교착 상태(deadlock)**
		- 두 개 이상의 프로세스가 서로 자원을 기다리며 무한 대기 상태에 빠지는 상황
	- **우선순위 역전(priority inversion)**
		- 우선순위가 높은 스레드가 우선순위가 낮은 스레드에 의해 대기하는 상황입니다. 
	- **기아(starvation)**
		- 특정 프로세스가 자원을 할당받지 못하고 계속 대가하는 상황입니다.
		- 동기화는 자원의 공정한 분배를 통해 기아를 방지 
### 공유 자원과 임계 구역 
- shared resource(공유 자원)
	- 여러 프로세스나 스레드가 동시에 접근할 수 있는 자원을 의미 
	- 공유 자원은 여러 프로세스가 동시에 접근해 데이터를 읽거나 수정할 수 있으므로 안전한 사용을 위해 임계 구역을 관리해야함 
- critical section(임계 구역)
	- 하나의 프로세스 또는 스레드가 공유 자원에 접근해 작업을 수행하는 코드 영역입니다. 
	- 만약 임계 구역을 관리하지 않으며 여러 프로세스가 동시에 공유 자원에 접근하면서 데이터 무결성이 손상될 위험이 있습니다. 
	- **임계 구역의 구조**
		- 진입 영역(entry section)
			- 임계 구역에 진입하기 전에 동기화 기법을 사용해 접근 허가를 요청하는 코드 
		- 임계 구역(critical section)
			- 공유 자원에 접근해 데이터를 수정하는 코드가 포함된 영역입니다.
			- 이 영역은 한 번에 하나의 프로세스만 접근할 수 있어야합니다. 
		- 출구 영역(exit section)
			- 임계 구역을 빠져나올 때 잠금으르 해제하고, 대기 중인 다른 프로세스에 접근 기회를 주는 코드 
		- 나머지 영역(remainder section)
			- 임계 구역과 관련 없는 일반적인 코드가 실행되는 부분 
	- **임계 구역 문제 해결 위한 조건**
		- 상호 배재(mutual exclusion)
			- 한 번에 하나의 프로세스(스레드)만 임계 구역에 접근 가능해야 합니다.
			- 임계 구역에 들어간 프로세스가 작업을 미치기 전까지 다른 프로세스가 접근하지 못하도록 방지합니다. 
		- 진행(progress)
			- 현재 임계 구역을 사용하는 프로세스가 없다면 대기 중인 프로세스가 즉시 임계 구역에 진입 가능해야 합니다. 
			- 특정 프로세스가 무작정 대기하는 기아 현상이 발생하면 안 됩니다. 
		- 유한 대기(bounded waiting)
			- 특정 프로세스가 무한정 기다리지 않도록 공정한 접근이 보장되어야 합니다. 
## 동기화 기법 
### 뮤텍스(mutex)
- 상호 배제를 보장하는 동기화 기법으로, 임계 구역을 보호하기 위해 한 번에 하나의 스레드만 공유 자원에 접근할 수 있도록 제한합니다. 
- 뮤텍스의 특징 
	- 하나의 스레드만 임계 구역에 접근할 수 있어야합니다. 
	- 자원을 소유한 스레드만 잠금을 해제할 수 있습니다. 
	- 교착 상태를 방지해야 합니다. 
- 뮤텍스의 2가지 상태 
	- 잠금(lock)
		- 스레드가 공유 자원에 접근하기 전에 뮤텍스를 잠급니다. 다른 스레드는 해당 뮤텍스가 잠긴 동안 자원에 접근할 수 없고, 잠금이 해제될 때까지 대기합니다. 
	- 잠금 해제(unlock)
		- 스레드가 작업을 완료하면 뮤텍스의 잠금을 해제해 다른 스레드가 자원에 접근할 수 있게 합니다. 
## 세마포어(semaphore)
- 프로세스가 동기화를 유지하고 상호 배제를 보장하기 위한 동기화 기법 

### 세마포어의 작동 방식 
- 세마포어는 자원에 접근할 수 있는 프로세스나 스레드의 수를 제한하는 카운터(counter)기반 기법입니다. 
	- **카운터** 는 공유 자원에 접근할 수 있는 '허용 수'를 나타냅니다. 
		- 세마포어를 획득하면 카운터가 감소하고, 해제하면 카운터가 증가합니다. 
		- 따라서, 공유 자원에 접근하려면 카운터 값이 감소해야 하고, 사용이 끝나면 카운터 값을 증가시켜 다른 스레드가 공유 자원에 접근할 수 있도록 합니다. 
	- **세마포어의 초깃값 종류**
		- **이진 세마포어(binary semaphore)**
			- 초깃값을 1로 설정해 뮤텍스처럼 작동하는 세마포어입니다. 
			- 한 번에 하나의 스레드만 공유자원에 접근 가능 
		- **counting semaphore**
			- 초깃값을 1보다 큰 값으로 설정하는 세마포어입니다. 
			- 여러 스레드가 동시에 공유 자원에 접근할 수 있도록 해 제한된 자원을 보호합니다. 
	- **세마포어의 작동 연산**
		- p 연산(또는 Wait연산)
			- 세마포어의 카운터를 감소시켜 지원 사용을 허용하는 연산입니다. 
			- 스레드는 임계 구역에 들어가기 전에 P연산을 호출ㄹ해 자원에 접근할 수 있는지 확인 
				- if counter  == 0: 
					- 자원이 모두 사용 중이므로 스레드는 blocked상태가 됩니다. 
				- elif counter > 0: 
					- 세마포어의 카운터 값을 감소시키고 자원에 접근
		- V 연산(또는 signal연산)
			- 세마포어의 카운터를 증가시켜 자원 사용을 해제하는 연산 
			- 자원 사용이 끝난 스레드는 V연산을 호촐해 카운터를 증가시킵니다. 
			- 자원 사용이 끝났으므로 대기 중인 스레드가 이를 깨워서 실행(wakeup)하게 됩니다. 
### 뮤텍스와 세마포어의 비교 
- 뮤텍스는 오직 하나의 자원을 소유하고 접근 가능한 반면, 세마포어는 여러 스레드가 동시에 자원을 접근할 수 있도록 허용 
	- **접근 제어**
		- 뮤텍스는 한 번에 하나의 스레드만 임계 구역에 접근할 수 있도록 설계된 상호 배제 매커니즘입니다. 이진 세마포어도 이와 유사하게 동작합니다. 
		- 카운팅 세마포어는 초깃값에 따라 동시에 여러 스레드가 임계 구역에 접근할 수 있도록 허용합니다. 
			- 예를 들어, 초깃값이 3으로 설정되면, 최대 3개의 스레드가 동시 접근 
	- **소유권**
		- 뮤텍스는 소유권 개념이 있어서 뮤텍스를 잠근 스레드만이 잠금 해제 가능 
		- 세마포어는 소유권 개념이 없으며, 카운터를 통해 자원에 동시 접근할 수 있는 스레드 수를 제한 
	- **사용 목적**
		- 뮤텍스는 주로 상호 배제를 구현하는 데 사용하며, 하나의 스레드만 특정 자원에 접근해야 할 때 적합 
		- 세마포어는 제한된 개수의 자원을 관리하는 데 사용하며, 여러 스레드가 공유 자원에 접근해야 하는 환경에서 유용합니다. 
	- **적용 사례**
		- **뮤텍스**는 파일이나 공유 메모리와 같은 단일 자원에 대한 접근을 조절할 때 사용 
		- **세마포어**는 생산자-소비자 문제와 같이 여러 프로세스간 작업 순서를 조정하거나 자원 가용성을 조절할 때 사용 
			- what is 생산자-소비자 문제(producer-consumer problem)?
				- 제한된 버퍼를 공유하는 소비자-생산자간 상호작용을 다룸
				- 생산자는 데이터를 생성해 버퍼에 추가하고, 소비자는 버퍼에서 데이터를 소비 
					- **버퍼 오버플로**
						- 생산자가 버퍼가 가득 찬 상태에서 데이터를 추가하려 할 때 발생 
						- 이 경우 생산자는 버퍼에 빈 공간이 생길 때까지 대기 
					- **버퍼 언더플로**
						- 소비자가 버퍼가 비어 있는 상태에서 데이터를 소비하려 할 때 발생 
						- 이 경우 소비자는 생산자가 데이터를 추가할 때까지 대기 
				- **해결책**
					- 빈 공간 세마포어 
						- 초깃값을 버퍼의 최대 크기로 설정해 생산자가 데이터를 추가할 수 있는 빈 공간이 있을 때만 추가할 수 있도록 제어 
					- 데이터 세마포어 
						- 초깃값을 0으로 설정해 버퍼에 데이터가 있을 때만 소비자가 소비할 수 있도록 제어
### 바쁜 대기와 블로킹 
- 자원에 대한 접근을 관리하는 방식 
- **바쁜 대기(busy waiting)**
	- 스레드가 자원에 접근할 수 있는지 확인하기 위해 CPU를 계속 사용하는 방식 
	- 스레드는 자원이 사용 가능할 때까지 무한 루프를 돌리며 상태를 확인하므로 CPU자원을 낭비 
	- 스핀락 기반의 뮤텍스나 세마포어는 바쁜 대기 방식 사용 가능 
		- what is spinlock?
			- 자원이 잠겨 있을 때 스레드가 계속해서 자원의 잠금 상태를 확인하며 대기하는 방식 
			- 이 경우 스레드는 자원이 해제될 때까지 무한 루프를 돌며 자원의 잠금 상태를 확인 
			- 이 방식은 짧은 임계 구역을 보호할 때는 효과적이지만, 긴 대기 시간이 필요할 경우에는 비효율적입니다. 
- **블로킹(Blocking)**
	- 스레드가 자원을 사용할 수 없을 때 대기 상태로 전환해 CPU 자원을 소비하지 않는 방식 
	- 스레드는 자원이 사용 가능해질 때까지 대기하고, CPU는 다른 작업 가능 
	- 뮤텍스와 세마포어는 일반적으로 블로킹 방식으로 구현 
		- 자원이 사용 중일 때 대기 중인 스레드를 블로킹 상태로 전환해 CPU 자원 낭비하지 않음 
### 이벤트 객체 
- 운영체제에서 동기화를 위해 사용하는 기법 중 하나로, 특정 사건이 발생했음을 프로세스나 스레드에 전달하는 역할 
	- 이벤트(Event)란?
		- 시스템에서 특정 사건이 발생했음을 알리는 신호 
- **이벤트 객체의 상태**
	- 시그널 상태(Signal state)
		- 이벤트 객체가 활성화된 상태로, 특정 사건이 발생했음을 의미 
	- 비시그널 상태(Non-signal state)
		- 이벤트 객체가 비활성화된 상태로, 해당 사건이 발생하지 않았음을 의미 
- **이벤트 객체 상태 변경함수**
	- SetEvent()
		- 이벤트가 발생하면 이벤트 객체를 시그널 상태로 설정해 대기 중인 프로세스나 스레드에 작업 시작 신호를 알림 
	- ResetEvent()
		- 작업이 완료되거나 조건이 바뀌면 이벤트 객체를 비시그널 상태로 설정해 프로세스나 스레드를 대기 상태로 전환 
- **시그널 상태의 유지 방식에 따른 두 가지 모드**
	- 자동 리셋(auto-reset)
		- 이 모드에서는 대기 중인 스레드 중 하나가 이벤트 객체의 시그널 상태를 감지하면 그 스레드만 깨어나고 이벤트 객체는 자동으로 비시그널 상태로 전환 
	- 수동 리셋(manual-reset)
		- 이 모드에서는 이벤트 객체가 시그널 상태로 설정되면 대기 중인 모든 스레드가 깨어납니다. 
		- 이벤트 객체는 ResetEvent()호출전까지 시그널 상태를 유지
- **note!!**
	- 이벤트 객체는 다른 동기화 기법인 뮤텍스나 세마포어처럼 자원 보호가 아니라 특정 조건이 충족되었음을 스레드에 전달하는 용도입니다. 
## 교착 상태 

### 교착 상태(deadlock)란
- 두 개 이상의 프로세스가 서로가 점유한 자원을 기다리면서 무한정 대기하는 상황을 의미 
	- 즉, 자원을 점유한 프로세스들이 서로 다른 프로세스가 가진 자원을 양보하면서 기다리며 아무것도 진행할 수 없는 상태를 의미 
- **교착 상태 발생 조건**
	- 상호 배제 
		- 자원은 한 번에 하나의 프로세스만 사용이 가능합니다. 
	- 점유와 대기(hold and wait)
		- 프로세스가 하나 이상의 자원을 점유한 상태에서 추가 지원을 요청하며 대기하는 상황 
	- 선점금지(non-preemption)
		- 프로세스가 점유한 자원을 사용이 끝날 때까지 강제로 회수할 수 없는 상태 
	- 환형 대기(Circular wait)
		- 프로세스들이 자원을 기다리는 순환 구조를 형성하는 상황 
	- 이 4가지 중 하나라도 제거되면 교착 상태를 예방 가능합니다. 

### 교착 상태 해결 방법 
- 예방(prevention)
	- 교착 상태의 4가지 중 하나 이상을 사전에 제거해 교착 상태가 발생하지 않도록 하는 방법 
	- 가장 확실한 해결책이지만, 자원 낭비나 성능 저하 문제 발생 가능 
		- **상호 배제 제거**
			- 자원을 공유 가능한 형태로 만들거나 자원을 복제해 여러 프로세스가 동시에 사용하도록 합니다. 
			- 이 방법은 공유 불가능 자원(프린터, 파일 쓰기 등)에는 적용 불가 
		- **점유와 대기 제거**
			- 프로세스가 필요한 모든 자원을 한꺼번에 요청하게 해서 프로세스가 자원을 점유하면서 추가 자원을 기다리는 상황을 방지합니다. 
			- 프로세스가 장기간 점유하게 되므로 효율성이 떨어질 수 있습니다. 
		- **선점 금지 제거**
			- 프로세스가 자원을 점유한 상태에서 다른 자원을 요청하면 점유한 자원을 강제로 반납 
			- 프로세스가 자주 중단되면 작업 수행이 원활하지 못할 수 있습니다. 
		- **환형 대기 제거**
			- 자원에 우선순위를 부여하고, 프로세스가 자원을 요청할 때 낮은 우선순위에서 높은 우선순위로 요청하도록 강제합니다. 
- 회피(avoidance)
	- 교착 상태의 가능성을 미리 예측하고 위험한 상황이 발생하지 않도록 조정하는 방법 
	- **은행원 알고리즘(banker's algorithm)
