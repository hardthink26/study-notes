## 운영체제의 개요 
- 운영체제의 정의 
	- 하드웨어와 소프트웨어를 연결하는 핵심 역할을 담당 
	- 사용자가 장치의 기능을 편리하게 활용토록 도움 
- 운영체제의 역할 
	- 하드웨어를 직접 제어하고 컴퓨터 자원을 효율적으로 관리
	- 사용자와 Application이 하드웨어를 쉽게 사용하도록 지원 

## 운영체제의 역할 
- **하드웨어 관리**
	- 장치 드라이버를 사용해 하드웨어와 통신하며, 사용자와 응용 애플리케이션이 하드웨어를 쉽게 사용하도록 합니다. 
- **프로세스 관리**
	- 운영체제는 프로세스의 생성, 종료, 상태 전환 등을 관리 
- **메모리 관리**
	- 한정된 메모리를 프로그램이 효율적으로 사용할 수 있도록 할당하고, 사용이 끝난 메모리는 다시 회수 
	- 메모리 단편화를 최소화 
	- 가상 메모리를 사용해 더 많은 프로그램이 실행되도록 합니다. 
- **파일 시스템 관리**
	- 파일 시스템을 사용해 파일을 생성, 수정, 삭제, 검색 가능 
	- 디렉터리로 파일을 체계적으로 정리 가능 
- **사용자 인터페이스 제공**
- **보안과 접근 제어**
	- 사용자 인증(user authentication):비밀번호, 생체 인증 등으로 사용자 신원 확인 
	- 파일 및 프로그램 권환 관리: 사용자의 권한에 따라 특정 파일이나 프로그램에 대한 읽기/쓰기/실행 권환 부여 
	- 암호화 및 보안 기법: 데이터를 보호하고, 악성 코드나 허용되지 않은 접근으로부터 시스템을 유지 

## 운영체제의 구성 요소 
- **커널(kernel)**
	- 하드웨어를 직접 제어하며 시스템 자원을 관리 
	- 주로 프로세스, 메모리, 파일 시스템, 장치 드라이버를 관리
- **사용자 인터페이스(UI)**
	- UI 유형 
		- 그래픽 사용자 인터페이스(GUI)
		- 명령줄 인터페이스(CLI)
- **시스템 라이브러리**
	- 운영체제에서 자주 쓰는 기능을 모아 놓은 소프트웨어집합(라이브러리)입니다. 
	- 대표적으로는 C표준 라이브러리 등등 
- **유틸리티**
	- 운영체제의 기능을 보조하고, 시스템 유지 보수와 관리 작업을 지원하는 시스템 프로그램

## 운영체제의 실행 과정
- 부팅(Booting)
	- 컴터 전원을 키고 운영체제가 실행되어 시스템이 사용할 준비가 된 상태 
- 과정 
	1. 부팅 시작
	2. 펌웨어 초기화 및 POST 수행 
		- 펌웨어는 CPU, memory, 그래픽 카드, 디스크 등 주요 하드웨어 초기화하고 하드웨어가 정상적으로 동작하는지 확인 -> 이 과정을 POST(Power-On Self Test)라고 함 
		- 하드웨어에 이상이 없다면 부트 장치(운영체제가 설치된 저장 장치)를 찾는 과정으로 감 
	3. 부트 로더 실행 
		- 펌웨어는 부트 순서에 따라 운영체제가 설치된 디스크를 찾는다. 
		- 만약 찾았다면, 부트 로더를 실행 
			- 부트로더는 운영체제를 메모리로 불러오는 Program
			- 부트로더는 운영체제의 핵심 파일(커널)을 메모리에 로드하고, 시스템 제어를 운영체제로 넘깁니다. 
			- 윈도우는 Windows Boot Manager, MacOs는 boot.efi, linux는 GRUB같은 부트 로더를 사용 
	4. 커널 로드 및 초기화 
		- 커널이 메모리에 로드되면 운영체제가 정상적으로 실행될 수 있도록 시스템 자원을 초기화하고, 기본 환경을 설정 
	5. 장치 드라이브 로드 및 하드웨어 초기화 
		- 장치 드라이버는 운영체제와 하드웨어 간 통신을 담당하고, 프린터, 키보드, 마우스, 네트워크 카드 등의 장치를 사용토록 설정합니다. 
	6. 시스템 서비스 및 데몬 실행 
		- 커널 초기화가 끝나면 운영체제는 시스템 서비스와 백그라운드 프로세스인 daemon을 실행합니다. 
		- 데몬은 네트워크 설정, 로그인 관리, 파일 시스템 서비스 등을 수행합니다. 
	7. 사용자 인터페이스 로드 
	8. 응용 프로그램 실행 준비

## 커널(kernel)
- definition
	- 하드웨어와 소프트웨어 사이에서 자원 관리 및 시스템 운영을 담당하는 운영체제의 프로그램 

### 커널의 종류 
- 모놀리식 커널(Monolithic kernel)
	- 운영체제의 핵심 기능을 모두 kernel space에서 실행합니다. 
		- kernel space는 파일 시스템, 장치 드라이버, 메모리 관리 등 운영체제의 주요 기능 담당 
	- 모놀리식 커널은 한 개의 커다란 실행 단위로 동작 
	- **장점**
		- 동일한 메모리 공간에서 모든 기능을 수행하므로 성능이 뛰어남 
		- 응용 프로그램이 운영체제의 커널을 거치지 않고, 직접 하드웨어를 제어하거나 시스템 자원을 관리하므로 처리 속도가 빠릅니다. 
	- **단점**
		- 한 기능에서 오류가 발생하면 전 시스템이 다운될 위험이 있습니다. 
		- 커널 크기가 커지면 유지 보수와 디버깅이 쉽지 않습니다. 
- 마이크로 커널(micro kernel)
	- 운영체제의 기능을 최대한 작고 간단하게 유지하려는 방식입니다. 
		- 커널 크기를 최소화하기 위하여 필수 기능만 커널 영역에서 실행하고 나머지 기능은 사용자 영역에서 실행합니다. 
	- **장점**
		- 시스템에 장애가 생겨도 전체 커널이 다운되지 않아서 안정성이 높습니다. 
		- 기능을 쉽게 추가하거나 삭제가 가능하여 유연성이 높습니다. 
	- **단점**
		- 사용자 영역과 커널 영역간 전환이 자주 발생하면 성능이 떨어질 수 있습니다. 
		- 설계 복잡, 유지 보수 어렵습니다. 
- 하이브리드 커널(Hybrid kernel)
	- monolithic kernel + micro kernel
		- 대부분의 기능을 커널 영역에서 실행하지만 특정 기능(일부 장치 드라이버, 네트워크 서비스)등을 사용자 영역에서 실행하는 방식 
	- 두 가지 방식을 혼합해야 하므로 설계가 복잡하고, 유지 보수가 어렵습니다. 
- 엑소 커널(Exo kernel)
	- 기존 커널 구조와 다르게 하드웨어 자원 관리를 최소화하는 방식입니다.
		- 운영체제가 직접 하드웨어를 관리해서 최대 성능을 제공
		- 커널에 의존하지 않고 자체적으로 최적화가 가능해서 유연함 
	- **단점**
		- 개발 복잡도가 높고 구현 어렵 
		- 모든 응용 프로그램이 하드웨어를 제어하면 충돌 가능성 생김 

## 시스템 호출 

### 시스템 호출이란? 
- 응용 프로그램이 운영체제의 기능을 요청할 때 사용하는 인터페이스입니다. 
- 운영체제는 응용 프로그램이 커널 기능(파일 시스템, 네트워크, 메모리 할당 등)에 직접 접근할 수 없도록 제한하고 시스템 호출을 통해서만 접근토록 합니다. 

### 커널 영역과 사용자 영역 
- 운영체제는 메모리를 커널 영역과 사용자 영역으로 분리해 관리 
	- 커널 영역 
		- 운영체제와 커널 코드가 실행되는 공간 
	- 사용자 영역 
		- 응용 프로그램, 사용자 프로세스 등이 실행되는 공간 

### 시스템 호출의 종류 
- **프로세스 관리**
	- 프로세스의 생성, 실행, 종료 등등 
	- 대표적인 관리 시스템 호출 
		- `fork()`
		- `exec()`
		- `exit()`
		- `wait()`
		- `kill()`
- **파일 관리**
	- 종류
		- `open()`
		- `read()`
		- `write()`
		- `close()`
		- `unlink()`
- **입출력 관리**
	- 종류
		- `ioctl()`:장치 제어(터미널 속성 변경 등)
		- `read()`
		- `write()`
		- `lseek()`:파일의 특정 위치로 이동 
- **메모리 관리**
	- 종류
		- `brk()`:프로세스의 힙(heap)영역 크기 조절 
		- `mmap()`: 파일을 메모리에 매핑
		- `shmget()`: 공유 메모리 할당 
		- `shmat()`: 공유 메모리 연결 
- **네트워크 통신**
	- 종류
		- `socket()`:
		- `bind()`: 소켓을 특정 소트에 전달 
		- `listen()`: 클라이언트 연결 요청 대기 
		- `accept()`: 클라이언트 요청 수락 
		- `send()`: 데이터 전송 
		- `recv()`: 데이터 수신 
### 시스템 호출 과정 
1. 응용 프로그램의 시스템 호출 요청 
	- 응용 프로그램이 시스템 자원을 활용하려고 운영체제에 시스템 호출을 요청하는 단계 
	- 이 요청은 사용자 모드에서 실행됩니다. 
2. CPU kernel 모드 전환 
	- CPU가 사용자 모드에서 커널 모드로 전환 
	- 시스템 호출이 발생하면 CPU의 제어권이 커널에 넘어가고, 실행 흐름이 응용 프로그램에서 운영체제로 변경 
		- 운영체제는 시스템 호출을 직접 실행하는 것이 아니라 내부적으로 syscall명령을 사용해 CPU에 커널 모드 전환을 요청 
		- syscall발생시, 트랩 또는 소프트웨어 인터럽트가 발생하고 CPU가 커널 모드로 전환 
			- 트랩(trap)
				- 시스템 호출 방생 시, 실행 흐름을 변경하는 이벤트 
			- software interrupt
				- 소프트웨어가 CPU에 특정 요청을 전달하는 인터럽트 
3. 시스템 호출 처리 
	- 커널이 요청한 시스템 호출의 종류를 분석하고, 해당 요청을 처리할 시스템 기능을 실행하는 단계
4. 결과 반환 및 사용자 모드 복귀 
	- 커널이 모든 요청을 처리하고 사용자 프로그램으로 다시 제어권을 넘기는 단계 
		- 이 단계에서는 요청 작업이 정상적으로 완료되었는지 확인하고, 반환값을 응용 프로그램으로 전달 
	- CPU를 커널 모드에서 사용자 모드로 전환하여 응용 프로그램이 실행을 계속할 수 있도록 합니다. 
5. 응용 프로그램에서 반환 결과 사용 

### CPU의 실행 모드 
- 실행 모드 구분은 **모드 비트(mode bit)** 를 사용해 구분합니다. 
	- 모드 비트가 0이면 커널 모드로 작동하고, 모드 비트가 1이면 사용자 모드로 전환됩니다.
